# Итоги работы над качеством подбора, демонстрацией и пилотом

Разделяем две вещи: **инженерная готовность** (код, тесты, документы, запуск демо) и
**доказательство качества** (эксперименты на синтетике). Зелёные тесты кода не доказывают
превосходства подбора.

## Исходная точка

Коммит до правок — `00d1ff2`. Конфигурация — `backend/config/mechanics.yaml` (γ = 0,8, κ = 1,15,
`test_stop_sd` = 0,40). Данные — D1 (сид 20261005) и D2 (20261006), по 3000 кандидатов и 100
потребностей. Воспроизведено: занижение грейда 0,394 и 0,393 (прежний отчёт: около 39 %), P@10
0,900 и 0,812 против 0,958 у B0 — совпало с прежним отчётом. Расхождение найдено одно: B1 и B2
были реализованы, но попадали в отчёт только при `--group validation`; прежний отчёт собран без
группы. B3 реализован, ответов в кэше нет (платный прогон не запускался по решению команды).

Внедрённых изменений механики нет: вариант γ = 0,70 снижал занижение, но ухудшал P@10 и завышение
на отложенных наборах, поэтому возвращён. `test_stop_sd` ниже и κ выше удлиняют тест до упора в
лимит заданий без выигрыша. Подробности и неопределённость — [сводка экспериментов](validation-experiments.md),
интервалы — в разделах M1 и M2 [отчёта](validation-report.md).

Вклад частей подбора (D1): отсечение по категории поднимает B1 и B2 с 0,44–0,45 до 0,80–0,81;
наш скор внутри блоков даёт ещё около +0,09 (0,900). Вклад вероятности принятия оценивается
отдельно рыночной симуляцией M6 (D1 выполнен, D2 не выполнен) и моделью принятия M7 (AUC 0,908);
релевантность и ожидаемое число принятых приглашений — разные цели, успех одной метрики не
доказывает другую.

## Проверки

```
cd backend && uv run ruff check . && uv run ruff format --check . && uv run mypy . && uv run pytest -m ""
cd frontend && npm run verify
cd backend && uv run --group validation python -m validation report
docker compose -p calibr-demo build
```

`pytest -m ""` — 3480 тестов, на чистом `main` красных было 6 (устаревшие тесты, исправлены в
этой ветке). Отчёт воспроизводится байт в байт (тест
`test_same_run_writes_same_report_byte_for_byte`).

## Недостигнутые пороги (не понижались)

M2 на D2 (0,734 при пороге 0,75), M10 на D2 (завышение 0,067, точное 0,540), M12, M13, M14, M15,
M16, M19, M22. Следующий шаг — механизм, который по данным D1–D3 снижает долю атакующих в топ-10
(LLM-помощники 5 % мест), и проверка на новом отложенном наборе: D9 и D10 после просмотра для
настройки не годятся.

## Внешние зависимости и действия для запуска

- B3: платный прогон Claude Sonnet через Agent SDK, около 579 $ полностью; не запускался.
- Запись демо: нужен подключённый Chrome-расширение или другой инструмент записи.
- Публичный стенд: домен, TLS, SMTP, настоящий ФСП ID, Keycloak не в режиме `start-dev` — список в
  [deploy.md](deploy.md).
- Пилот: участники, согласия, эксперты, площадка — [чек-лист](pilot/launch-checklist.md).
