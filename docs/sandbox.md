# Проверка подбора на своём наборе пар

Жюри проверяет подбор на закрытом наборе пар «вакансия — кандидат» и сверяет цифры со стендом
валидации. Команда из `backend/`:

```bash
uv run python -m validation sandbox --dataset ../docs/examples/sandbox-set.json
```

## Формат набора

JSON с тремя списками:

- `vacancies` — `{id, text}`: вакансия текстом; разбирается тем же разбором текста, что в кабинете
  работодателя;
- `candidates` — `{id, specialization, grade, levels}`: персонаж с заявленным грейдом и уровнями θ
  по темам специализации (код темы → число; пропущенная тема — 0). Персонаж проходит адаптивный
  тест в симуляторе стенда — та же модель ответов, что у D1 — и получает категорию тем же
  сценарием, что HTTP; не прошедший тест попадает в нижний блок «грейд не подтверждён»;
- `pairs` — `{vacancy, candidate, relevance}`: разметка релевантности 0–3; пара без разметки — 0.

Пример — [examples/sandbox-set.json](examples/sandbox-set.json).

## Итог

По каждой вакансии и в среднем: доля релевантных (разметка не ниже 2) в топ-10 и nDCG@10 — теми
же функциями `validation.metrics`, что M1 и M2 отчёта стенда, — и выдача с соответствием.

## Изоляция

Песочница строит свой стенд в памяти: банк заданий, пул кандидатов и подборки живут в процессе
команды и исчезают с ним. Базы продукта она не открывает, загруженные персонажи и вакансии в
обычную выдачу не попадают (`tests/test_sandbox.py`). Загрузка через интерфейс не сделана.
