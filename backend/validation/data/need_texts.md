# Размеченные тексты потребностей — формат набора

Набор для M21 ([`docs/validation-plan.md`](../../../docs/validation-plan.md), D5 и M21): тексты
вакансий с разметкой по полям. D5 лежит рядом — `d5_need_texts.yaml`; прогон:

```sh
uv run python -m validation parsing                      # D5
uv run python -m validation parsing --dataset <файл>     # другой набор того же формата
```

Тексты нужны только для проверки разбора: в платформу они не импортируются и в выдаче не
показываются. D5 — отложенный набор: по нему не подбирают правила и словарь синонимов
(`config/synonyms.yaml`) и не обучают модели ([ADR 0002](../../../docs/adr/0002-text-understanding-port.md)).

## Файл

YAML с одним ключом `texts` — список записей, одна запись на текст:

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | Свой идентификатор записи |
| `source` | да | Откуда текст: ссылка |
| `date` | да | Когда текст взят, `ГГГГ-ММ-ДД` |
| `checked_by` | да | Чья разметка: `model` — разметка модели, человек запись не проверял; иначе — кто из команды проверил |
| `text` | да | Текст как есть |
| `out_of_catalog` | нет, `false` | Специализации нет в справочнике (1С, геймдев и т. п.); остальные поля такой записи не размечаются |
| `specialization` | нет | Код специализации из `config/catalog.yaml` |
| `grade` | нет | Код грейда |
| `stack` | нет, `[]` | Коды технологий, которые названы в тексте |
| `work_format` | нет | `office`, `hybrid` или `remote` |
| `city` | нет | Город — каноническое название, как в `config/synonyms.yaml` |
| `salary_from`, `salary_to` | нет | Вилка из текста, рубли в месяц, как написано; без пересчёта «на руки» |

Чего в тексте нет, того нет и в разметке: поле опускается или `null`. Важность тем не размечается —
её выводит домен из стека.

## D5

Тексты — открытые вакансии hh.ru, Хабр Карьеры и getmatch: заголовок, блок над описанием, как
его показывает площадка (вилка, город, опыт, формат), и описание как есть. HTML снят, контакты
заменены на `[контакт]`. Не вошли тексты не про ИТ, попавшие в выдачу поиска, и тексты, где
ассистенты разработки названы по имени: их не пропускает стоп-лист git-хуков. У всех записей `checked_by: model`: по решению команды разметку делает
модель, человек каждую запись не проверяет ([план валидации](../../../docs/validation-plan.md),
D5 и M21). Правила разметки:

- **грейд** — по слову уровня (стажёр, junior, middle, senior; «старший», «ведущий», lead —
  senior), при двух уровнях — первый названный; без слова — по требуемому опыту: до 3 лет —
  junior, 3–6 — middle, больше 6 — senior;
- **стек** — технологии вакансии, названные в тексте, включая «будет плюсом»; без кода в
  справочнике не размечаются, стек всей компании и упоминания вне работы — тоже;
- **формат** — при нескольких предложенных самый свободный: remote, затем hybrid, затем office;
- **город** — из блока над описанием, иначе первый названный как место работы; вне словаря —
  `null`;
- **вилка** — рубли в месяц, одна сумма — обе границы; другая валюта, оплата за час или смену —
  не размечается.

## Как считается

- Специализация, грейд, формат и город — доля текстов из справочника с точным совпадением,
  `null` с `null` — совпадение. Ответ «вне справочника» на тексте из справочника — промах.
- Стек — micro-F1 по всем текстам из справочника.
- Вилка — на текстах, где она размечена: обе границы совпали точно.
- «Вне справочника» — полнота по текстам с `out_of_catalog: true`.
- Базовая линия для специализации и грейда — самый частый класс разметки.
