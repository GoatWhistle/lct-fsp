# Форма обратной связи

Три формы: кандидат (две части), работодатель (по подборке и итоговая), эксперт (по паре идёт по
[рубрике](rubric.md), здесь — вопросы о процессе). Шкалы Ликерта — 1–5, где 1 — «совсем нет»,
5 — «полностью». Идентификатор участника в форме — псевдоним
([data-collection.md](data-collection.md)), не имя. Поля, отмеченные `*`, обязательны; остальные
можно пропустить. Названия полей в скобках — столбцы таблиц сбора.

## Кандидат: после теста

Заполняется сразу после завершения теста (или после выхода из него — тогда обязательна часть А).

**А. Если тест не завершён** (`abandon_reason`*):
- не хватило времени;
- задания слишком трудные;
- задания не по моей специализации;
- не понял интерфейс;
- сбой стенда;
- не захотел продолжать, потому что: ___ (свободный ответ).

**Б. Для всех:**

1. Сколько минут вы потратили на тест, по вашим ощущениям? (`self_time_min`*)
2. Длина теста: слишком короткий / подходящий / слишком длинный. (`length_rating`*)
3. Задания соответствовали выбранному грейду: 1–5. (`items_fit`*)
4. Результат (категория, уровень, профиль по темам) похож на вашу самооценку: 1–5. (`result_fit`*)
   Если нет — что именно не так? (`result_comment`)
5. Объяснение результата понятно: 1–5. (`explain_clear`*)
6. Использовали ли вы во время теста: поиск в интернете / справочники и документацию / чужую
   помощь / ничего из этого / генеративную модель? Выбор можно отметить без последствий;
   ответ нужен, чтобы понимать условия, а не наказывать. (`aid_used`*)
7. Что было неудобно или непонятно? (`free_text`)

## Кандидат: после повторного прохождения

1. Задания в повторе показались знакомыми: нет / отдельные / многие. (`repeat_familiarity`*)
2. Результат повтора совпал с первым по ощущению: да / нет. (`repeat_match`*)
3. Что изменилось между прохождениями (готовились, меняли подход)? (`repeat_change`)

## Кандидат: после приглашений

Заполняется после ответов на все приглашения или истечения срока.

1. Приглашений получено — подставляется автоматически (`n_invites`).
2. По каждому приглашению: решение (принято / отклонено / без ответа) подставляется из
   платформы; ответ на вопрос «почему» — (`decision_reason`*): вилка устроила / вилка не
   устроила / компания не интересна / роль не подходит / не ищу работу / формат работы не
   подходит / другое: ___.
3. Вы ответили бы так же, если бы приглашение пришло не в рамках пилота? (`would_same`*): да /
   скорее да / скорее нет / нет / не знаю.
4. Приглашение содержало достаточно информации для решения: 1–5. (`invite_info`*)
5. Вас беспокоит, что работодатель видел обезличенную карточку до вашего согласия: нет / немного
   / да. (`privacy_ok`*) Почему? (`privacy_comment`)
6. Подсказки «что поднимет выше» (если вы их видели) полезны: 1–5 / не видел(а). (`tips_useful`)
7. Порекомендуете платформу коллегам: 0–10. (`nps`*)

## Работодатель: по подборке

Заполняется один раз на потребность, после просмотра подборки.

1. Время начала описания и решения по подборке отмечает платформа; кроме того, работодатель
   называет сам: сколько минут ушло на потребность от начала до решения? (`self_time_min`*)
2. «Система поняла так» отразило вашу потребность: 1–5; что исправили вручную? (`parse_fit`*,
   `parse_edits`)
3. По каждой карточке подборки (`card_id`; порядок показа соответствует выдаче, оценку ставит
   работодатель):
   - полезность 0–3: 3 — позвал бы сразу; 2 — позвал бы; 1 — только при нехватке; 0 — нет
     (`card_useful`*). Шкала повторяет [рубрику экспертов](rubric.md) намеренно: так можно
     сравнить работодателя и экспертов;
   - объяснение подборки (вклад тем) помогло принять решение: да / нет / не открывал(а)
     (`card_explain`).
4. Кого из подборки вы пригласили бы без ограничений бюджета? (`card_would_invite`*: да / нет по
   каждой карточке.)
5. Есть ли в подборке очевидно неподходящие? Сколько и почему? (`obvious_misses`, `miss_reason`)
6. Не оказалось ли в подборке тех, кого вы ожидали увидеть, но не увидели? (свободный ответ)
7. Как вы обычно отбираете кандидатов на такую позицию и сколько минут это занимает?
   (`baseline_minutes`*; нужен как база для [критерия 5](decision-criteria.md#5-затраты-времени-работодателя).)

## Работодатель: итоговая форма

1. Подборка сэкономила время по сравнению с обычным отбором: 1–5. (`saved_time`*)
2. Вилка зарплаты в приглашении: форма понятна 1–5; подсказка по вилке (если была) полезна 1–5.
   (`salary_form`, `salary_hint`)
3. Вам важно, что контакты скрыты до принятия: 1–5. (`contacts_hidden_ok`)
4. Пользовались бы вы платформой дальше: да / скорее да / скорее нет / нет. (`would_continue`*) Что
   должно измениться? (`must_change`)
5. Какой сигнал в карточке вам больше всего помог (тесты, ФСП, стек, категория)? (`top_signal`)
6. Что вы не поняли? (`free_text`)

## Эксперт: после оценки

1. Сколько в среднем минут занимала пара (`avg_min_per_pair`*).
2. Какие формулировки рубрики были неоднозначны, номера пар. (`ambiguity_notes`)
3. Что вам мешало оценивать по обезличенной карточке? (`card_gaps`)
4. Вы подозреваете, что видели скор или место в выдаче: нет / возможно / да. (`blinding_check`*)

## Проведение

Формы заполняются на платформе опроса или таблице, выбранной командой ([чек-лист](launch-checklist.md)),
по ссылке с псевдонимом. Свободные ответы хранятся как есть, без правки. Ничего, что участник
написал в свободных полях, не используется как доказательство качества без отдельного разбора
и согласия на цитирование.
