# Пилот на людях: материалы

Материалы для пилота в одной специализации — **бэкенд**. Пилот **не проводился**: ни одного
участника, ответа или оценки в этих файлах нет, все числа ниже — пороги и планы, а не результаты.
Синтетические данные стенда ([отчёт валидации](../validation-report.md)) пилот не заменяют и в
его выводы не подмешиваются: у пилотных данных свой источник (`source = pilot`), см.
[сбор данных](data-collection.md).

**Почему бэкенд:** на нём построены демо-сценарии и маршрут жюри ([для жюри](../for-jury.md)),
а ИТ-аудиторию с опытом в этом направлении проще всего набрать.

## Связь с планом валидации

При проведении пилот должен собрать данные для пунктов
[плана валидации](../validation-plan.md), помеченных «ожидает данных»:

- **D8** — не меньше 20 человек проходят тест дважды: метрики **M9** (стабильность грейда) и
  **M11** (дискриминативность семейств) на живых ответах;
- **D4/M20** — независимая разметка пар по шкале 0–3: согласие модели с людьми на реальных
  потребностях, а не на синтетических.

Критерии продолжения заданы до пилота и правятся только записью в журнале изменений
[decision-criteria.md](decision-criteria.md#журнал-изменений), как и сам план валидации.

Готовность этого пакета означает подготовку протокола и форм. Она не требует уже набранных
участников и не закрывает метрики D8/D4/M20: их результат появится только после сбора
и анализа данных. Проведение пилота — отдельный этап по чек-листу запуска.

## Что пилот может и не может показать

Пилот на 20–30 кандидатах и 3–5 работодателях показывает, **проходим ли процесс** на живых людях:
доходят ли до конца теста, читаем ли объяснение, не тратит ли подборка время работодателя, есть ли
грубое расхождение с мнением экспертов. Он **не доказывает** превосходство подбора над базовыми
линиями и не оценивает редкие эффекты: границы — в
[ограничениях малой выборки](decision-criteria.md#ограничения-малой-выборки).
