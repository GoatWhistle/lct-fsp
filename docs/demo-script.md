# Сценарий демо: 5–6 минут

Стенд: `scripts/demo.sh up` (интерфейс http://localhost:3100, письма http://localhost:8125) или
основной стенд с `DEMO_MODE=true` и засевом ([запуск](running.md)). Заранее: два окна браузера
(кандидат и работодатель), русский язык, светлая тема. Учётки: `employer@demo.example`,
`devops-middle-fsp@demo.example`, пароль `demo-2026`. Тот же маршрут без слов проходит
`frontend/e2e/defense.spec.ts` и `defense-vacancy.spec.ts`.

Позиционирование в одной фразе: подбор по уровню, подтверждённому тестом, а не по резюме;
защита затрудняет накрутку, но не исключает её.

| Время | Показать | Сказать |
|---|---|---|
| 0:00–0:25 | Главная, переключение RU/EN и темы | Это платформа подбора ИТ-специалистов с обратной механикой: инициатива у работодателя, а проверка навыков — у системы. Что указано в резюме, на категорию не влияет. |
| 0:25–1:10 | Окно кандидата: «Новый тестовый кандидат» (режим жюри) → опрос → выбор грейда | Кандидат выбирает направление и грейд сам, но проверяет его адаптивный тест. Задания у каждого свои: экземпляры строятся из семейства, ответ считается кодом, поэтому пересланные задания бесполезны. |
| 1:10–2:00 | Три-четыре ответа в тесте; «задание N, не больше 30» | Тест подбирает следующее задание по текущей оценке и показывает не точку, а уровень с погрешностью. Экспресс-тест в демо — 8 заданий, обычный — до 30. |
| 2:00–2:40 | Результат: профиль навыков по темам, вероятность каждого грейда, категория | Итог — профиль по темам с погрешностью и категория: специализация на грейд. Не хватило уверенности — категории нет, а не выдуманная. Кандидат без истории ФСП получает нейтральную пометку, штрафа нет. |
| 2:40–3:10 | Выйти → «Войти через ФСП ID» → `fsp-winner` → достижения | Профиль связан с ФСП ID по OIDC. Достижения ФСП — самый весомый сигнал, но категорию они не меняют. |
| 3:10–3:50 | Окно работодателя: `employer@demo.example` → «Новая потребность» → вставить текст вакансии → разобрать | Работодатель описывает потребность словами, разбор виден по полям, неуверенные выделены. Разбирает правило или локальная модель, ранжирует модель никогда. |
| 3:50–4:30 | «Сформировать подборку» → карточка → «Почему этот кандидат» | Выдача идёт из категории теста: точный грейд, близкие, неподтверждённые ниже. У каждого есть соответствие и вероятность принятия, а объяснение раскладывает скор по темам, сумма вкладов равна скору. |
| 4:30–4:50 | Карточка кандидата, показать обезличенный вид | До принятия работодатель видит только обезличенную карточку: без ФИО, фото, возраста, вуза и контактов — это проверяется на бэкенде, а не в интерфейсе. |
| 4:50–5:20 | «Пригласить»: описание и вилка «от–до» в рублях, контакт → отправить | Вилка обязательна и указана в месяц до вычета НДФЛ, у приглашения есть недельный бюджет. Лучшим кандидатам не приходит полсотни писем. |
| 5:20–5:50 | Окно кандидата: «Приглашения» → вилка видна до общения → «Принять» → сообщение | Кандидат видит условия до разговора. После принятия контакты раскрываются. |
| 5:50–6:00 | Окно работодателя: приглашение → ФИО, контакты, переписка | Контакты открылись только теперь. Отклик на вакансию работает так же, как дополнительный путь. Спасибо. |

## Запасные ходы

- Тест затянулся: сразу войти `devops-middle-fsp@demo.example` — категория и профиль готовы.
- Нет подборки: у демо-работодателя три потребности уже с подборками.
- ФСП ID не отвечает: Keycloak стартует около минуты; вход по email работает без него.

## Видео

Записи экрана в репозитории нет. Инструмент записи GIF (расширение Chrome) на момент
подготовки не подключился: «Browser extension is not connected», поэтому сквозной проход выполнен
автотестами Playwright на изолированном стенде, а не живой записью в браузере.
