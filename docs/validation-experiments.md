Решение: γ = 0,80 оставлен. Отказ от γ = 0,70 принят после просмотра результатов на D9 и D10, поэтому наборы больше не отложенные. Снижение порога улучшает совпадение грейда, но подборка на отложенных
наборах не выигрывает, а завышение растёт — вывод «порог уверенности надо снижать» не
подтверждён. Неопределённость: в [отчёте M1](validation-report.md#m1-доля-релевантных-в-топ-10) разница нашей
выдачи и B0 по P@10 — −0,058 на D1, 95 % интервал [−0,086; −0,029], и −0,146 на D2 [−0,189; −0,105]
(бутстрап по 100 потребностям): проигрыш B0 статистически не нулевой, выигрыш у B1 и B2 — тоже
(+0,46 и +0,45 на D1, интервалы далеко от нуля). Вклад отсечения и скора разделяет таблица
«в наших блоках» в том же разделе: B1 и B2 внутри наших блоков 0,80–0,81 (D1) против 0,44–0,45 на
всём пуле, наш скор внутри блока даёт ещё +0,09.

## Из кого состоит топ-10

Диагностика на D1 (не настройка), 200 кандидатов на специализацию, 1000 мест,
`validation.experiments.top10`.

| Причина нерелевантности места | Наша выдача, γ 0,80 | Наша, γ 0,70 | B0, γ 0,80 |
|---|---|---|---|
| Релевантные | 0,855 | 0,818 | 0,848 |
| Помощник с LLM | 0,050 | 0,076 | 0,095 |
| Утечка банка | 0,023 | 0,022 | 0,015 |
| Накрутчик резюме | 0,012 | 0,011 | 0,006 |
| Честный, темы ниже требований | 0,029 | 0,045 | 0,031 |
| Блок «близкие» | 0,031 | 0,023 | — |

В этом уменьшенном пуле атакующие персонажи занимают 8,5 % нерелевантных мест относительно
всех мест нашей выдачи при γ = 0,80 (0,050 + 0,023 + 0,012); при γ = 0,70 — 10,9 %.
Это состав ошибок, а не причинная оценка влияния атак на качество ранжирования.

При 200 кандидатах на специализацию наша выдача имеет P@10 0,855 против 0,848 у B0:
проигрыш основного отчёта здесь не воспроизводится. Поэтому таблица не устанавливает
причину разрыва 0,900 против 0,958 на полном D1 с 600 кандидатами на специализацию
и ничего не устанавливает о составе ошибок полного D2. Гипотеза о ведущей роли
занижения грейда пока не подтверждена и не опровергнута этим разбором.

`validation.experiments.top10` относит нерелевантное место к первой подходящей группе:
персонаж-атакующий, затем неточная категория, затем истинный грейд или темы ниже требования.
Эти признаки могут пересекаться; приоритет классификации скрывает пересечения.
Пропущенных релевантных кандидатов скрипт не разбирает. Следующий эксперимент должен
сопоставить полный пул с основным отчётом и показать отдельно допуск по категории,
сортировку внутри категории и состав пропущенных релевантных кандидатов.

## Потолок показов семейств (M13)

D3, 100 кандидатов на специализацию, один параметр за прогон, `validation.experiments.grade`:

| Вариант | Завышение | Занижение | Точное | Заданий | Упор в лимит | sd(z) |
|---|---|---|---|---|---|---|
| база: `exposure_top_k` 2, `exposure_max_rate` 0,5 | 0,017 | 0,373 | 0,610 | 21,7 | 0,13 | 0,925 |
| `exposure_top_k` = 1 | 0,016 | 0,388 | 0,596 | 23,2 | 0,18 | 0,914 |
| `exposure_max_rate` = 0,7 | 0,023 | 0,375 | 0,602 | 19,4 | 0,11 | 0,983 |
| оба | 0,020 | 0,372 | 0,608 | 18,0 | 0,05 | 1,048 |

Вариант с обеими правками сократил среднее по специализациям медианное число заданий
с 21,7 до 18,0 (примерно на 17 %). Точное совпадение грейда — 0,608 против 0,610;
без интервала разности это не доказательство эквивалентности качества.
sd(z) = 1,048 находится внутри используемого в плане диапазона 0,9–1,1,
поэтому одного превышения единицы недостаточно для вывода о нарушенной калибровке.
Здесь приведено среднее по специализациям; план требует диапазон по каждой специализации,
поэтому это среднее также не доказывает прохождение проверки калибровки.

Более высокий потолок разрешает чаще показывать семейство. Увеличение риска утечки
для этого варианта — гипотеза: M14/M15 с ним не приведены. Таблица также не содержит
парного сравнения с фиксированным бланком, необходимого для вердикта M13.
Вариант не внедрён; его влияние на M13 и устойчивость к утечке остаётся непроверенным.

## Что не удалось и следующий шаг

- Детектор утечки: TPR 0,07–0,14 при FPR до 0,10 ([M15](validation-report.md#m15-детектор-утечки)).
- LLM-помощник: помечено 0,164 попыток с завышением при пороге 0,70
  ([M16](validation-report.md#m16-llm-помощник)).
- Завышение на сдвинутом генераторе D2 и D10 выше порога 0,05.
- Следующий шаг: локализовать проигрыш B0 на полном пуле D1/D2, затем выбрать механизм
  для проверки по выявленной причине. Проверенные настройки γ и κ не дали подтверждённого
  выигрыша; это не доказывает, что прочие варианты исчерпаны или требуется прокторинг.
  Независимую оценку выбранного варианта провести на новом заранее зафиксированном наборе.
- B3 не прогонялся: платный прогон не согласован, сравнение с B3 — «ожидает данных».

## Воспроизведение

```
cd backend
uv run --group validation python -m validation report                      # D1, D2
uv run --group validation python -m validation report --sets d9,d10 --report ../docs/validation-holdout-g08.md
uv run python -m validation.experiments.grade --candidates 100 --pairs 100 --set grade_confidence=0.7
uv run python -m validation.experiments.top10 --set d1 --candidates 200
```

Последняя команда воспроизводит только уменьшенную диагностику. Значение
`--candidates 600` задаёт размер полного пула на специализацию; перед интерпретацией
такого прогона необходимо сверить остальные условия и P@10 с основным отчётом.
Дополнительный разбор пропущенных кандидатов требует расширения диагностического инструмента.
