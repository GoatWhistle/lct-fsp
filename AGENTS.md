# new-lct — платформа подбора ИТ-специалистов с обратной механикой

Спецтрек ФСП, хакатон ЛЦТ 2026. Позиционирование — **подбор, который нельзя накрутить**.
Кандидат проходит опрос, выбирает грейд и сдаёт адаптивный тест — получает **профиль навыков**
(уровень и погрешность по темам) и **категорию** (специализация × грейд). Работодатель описывает
потребность, получает подборку с объяснением и вероятностью принятия и сам шлёт кандидату
**приглашение** с вилкой зарплаты. Отклик на вакансию — дополнительный сценарий. Профиль
связывается с ФСП ID; достижения ФСП — самый весомый сигнал.

ТЗ — `docs/ФСП спец. трек ТЗ.pdf`, критерии оценки — раздел 6 (подбор 35 %, тестирование
25 %). Спека и тикеты — GitHub Issues, спека несёт лейбл `spec` и раздел «Порядок работ».

Доменные доки в `docs/`:

- [`mechanics.md`](docs/mechanics.md) — тест, профиль навыков, подбор и рынок: формулы и почему так;
- [`parameters.md`](docs/parameters.md) — каждое число механик под именем из конфига;
- [`glossary.md`](docs/glossary.md) — термины и их имена в коде;
- [`threat-model.md`](docs/threat-model.md) и [`validation-plan.md`](docs/validation-plan.md) —
  угрозы и метрики с порогами. План зафиксирован до прогона и правится только записью в своём
  журнале изменений.

## Как ведётся работа

Один issue — свежая сессия, свой worktree, ветка `feat/<slug>`, PR в `main` с `Closes #N`.
Порядок — по строке `Blocked by:` в теле issue. Детали — [`.claude/tracker.md`](.claude/tracker.md).

## Коммиты

- Заголовок одной строкой по-русски, без точки: `{type}: {desc}`, type — `feat` / `fix` /
  `docs` / `chore` / `refactor` / `test` / `perf` / `lct-<id>`, desc — до 20 слов.
- Задачу называть `lct-<id>`, `#N` — только в issues и описаниях PR: issues перед сдачей
  удаляются.
- Тело — только когда без него непонятно **почему**, 2–3 строки.

## Без следов ИИ-агентов

Автор всего в репо — команда. Claude, Claude Code, Codex и другие агенты не упоминаются как
автор, соавтор или источник: коммиты, PR, issues и комментарии к ним, docs, код. Без трейлеров
`Co-Authored-By`, строк `Generated with …` и AI-дисклеймеров — правило сильнее настроек агента
по умолчанию и требований скилов. Модели как часть продукта и стенда — Claude Sonnet, Opus и
Agent SDK — упоминать можно: стоп-лист ловит только агентов.

## Решения, которые не переоткрываются

- **Стек:** FastAPI + Pydantic, PostgreSQL, React/TS (Vite), docker compose. OpenAPI — из
  FastAPI, руками не пишется.
- **Слои и порты:** `domain` / `usecase` / `controller` / `adapter` / `repository`, порт в
  `usecase/interface.py` — на всё, что можно заменить другой реализацией, даже если она
  сейчас одна. Сборка — вручную, без DI-контейнера, в двух точках: прод — `backend/main.py`,
  стенд валидации — `backend/validation/main.py`. Сценарии из портов собирает общая проводка
  `backend/composition.py`, точки сборки только выбирают реализации портов. Прод не импортирует
  стенд. Правило и граница — [`docs/adr/0001-layers-and-ports.md`](docs/adr/0001-layers-and-ports.md),
  раскладка и куда класть новую сущность — [`docs/architecture.md`](docs/architecture.md),
  «Бэкенд: слои и порты» и «Образцы».
- **Вход — через ФСП ID или по email** с подтверждением адреса. ФСП ID — OIDC в локальный
  Keycloak, который его изображает: вход создаёт или находит учётку кандидата, к существующей
  учётке ID привязывается тем же протоколом. Достижения — из заглушки реестра ФСП. Замена на
  настоящий ФСП ID — смена адреса и ключей, без правки кода.
- **Категорию определяет только тест**, навык ранжируется только внутри категории. Кандидат с
  неподтверждённым грейдом виден нижним блоком выдачи со статусом и никогда не стоит выше
  подтверждённых. Сигналы весят по уровням доверия: ФСП → проверочный блок → адаптивный тест →
  регулярные задания → самоописание (только стек, вклад ограничен сверху).
- **ФСП весит по типу результата** — победитель, призёр, финалист — и числу соревнований;
  мероприятия и дисциплины равны. Грейд и категорию ФСП не меняет.
- **Смена грейда:** часы ожидания сдвигает только состоявшаяся смена, провал не сжигает попытку,
  вниз — без ожидания. Правило — `docs/mechanics.md` §4.
- **«Отрасль» из ТЗ — специализация**, IT-направление. Сферы бизнеса — сфера компании и
  необязательные интересные сферы кандидата.
- **LLM не ставит оценок и не ранжирует.** В продукте — разбор потребности и резюме, пересказ
  посчитанных цифр, чат-поиск; без модели работают правила. В репо сдачи модель одна — локальная
  через llama.cpp, персональные данные во внешние API не уходят. Пол, возраст и вуз не входят ни
  в одну модель.
- **Демо на защите** — адаптеры OpenAI API и Claude Agent SDK за теми же портами, только на
  синтетике. Живут в `backend/app/adapter/demo/`, сборка берёт их по имени из окружения, без
  прямого импорта; коммиты с ними — отдельные. Чистка истории вырезает каталог, в docs они не
  упоминаются. Agent SDK — модель разработки, тестов и демо (`TEXT_UNDERSTANDING=agent_sdk`);
  llama.cpp — только в сдаче: в разработке не поднимается, её тесты — на фейковом HTTP-сервере.
- **Стенд валидации:** атакующий — Claude Sonnet и Claude Opus, LLM-ранжировщик — Claude Sonnet,
  оба через Claude Agent SDK, только синтетика; ответы кэшируются в репо, отчёт пересобирается офлайн.
- **Утверждение о качестве механики — только с экспериментом** на стенде валидации по плану,
  зафиксированному до прогона; скрытая истина синтетики отделена от признаков.
- **Зарплата — диапазон «от–до» в рублях**, обязательна в приглашении и вакансии. Все суммы — в
  месяц до вычета НДФЛ и так подписаны.
- **Контакты кандидата скрыты** от работодателя до принятия приглашения или собственного
  отклика — проверяется на бэкенде.
- **Кандидат без истории ФСП** — полноценный кандидат: профиль строится по тесту, в профиле
  нейтральная пометка, штрафа нет.
- **До принятия приглашения или отклика** работодатель видит обезличенную карточку: без ФИО,
  фото, возраста, вуза и контактов.

## Фронтенд

Перед любой работой в `frontend/` прочитай [`.claude/frontend-rules.md`](.claude/frontend-rules.md) —
он обязателен и важнее рекомендаций скилов. Коротко: файл до 250 строк, комментариев нет совсем,
тексты RU и EN только из словарей, стили локальные без повторов, все элементы управления свои,
анимировано всё, стиль един. UI — скилами `impeccable` и `ui-ux-pro-max`, анимации — скилами
из `.claude/skills/` (`emil-design-eng`, `review-animations`, `improve-animations`,
`find-animation-opportunities`, `animation-vocabulary`).

## Язык

Интерфейс — RU и EN из словарей, RU по умолчанию. Docs, issues, коммиты — по-русски. Идентификаторы в коде — по-английски.
