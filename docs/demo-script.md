# Сценарий демо: 5–6 минут

Стенд: `scripts/demo.sh up` (интерфейс http://localhost:3100, письма http://localhost:8125) или
основной стенд с `DEMO_MODE=true` и засевом ([запуск](running.md)). Заранее: два изолированных
профиля или контекста браузера (кандидат и работодатель), русский язык, светлая тема.
Два обычных окна одного профиля разделяют cookie и не сохраняют разные роли.
Учётки: `employer@demo.example`,
`devops-middle-fsp@demo.example`, пароль `demo-2026`. Тесты
`frontend/e2e/defense.spec.ts` и `defense-vacancy.spec.ts` покрывают отдельные части
маршрута; ограничения перечислены в разделе о видео ниже.

Позиционирование в одной фразе: подбор по уровню, подтверждённому тестом, а не по резюме;
защита затрудняет накрутку, но не исключает её.

| Время | Показать | Сказать |
|---|---|---|
| 0:00–0:25 | Главная, переключение RU/EN и темы | Это платформа подбора ИТ-специалистов с обратной механикой: инициатива у работодателя, а проверка навыков — у системы. Что указано в резюме, на категорию не влияет. |
| 0:25–1:10 | Окно кандидата: «Новый тестовый кандидат» (режим жюри) → опрос → выбор грейда | Кандидат выбирает направление и грейд сам, но проверяет его адаптивный тест. Экземпляры заданий строятся из семейств, ответ считается кодом. Вариативность ограничивает пользу готовых ответов, но не исключает помощь по знакомому семейству. |
| 1:10–2:00 | Три-четыре ответа в тесте; «задание N, не больше 30» | Тест подбирает следующее задание по текущей оценке и показывает не точку, а уровень с погрешностью. Экспресс-тест в демо — 8 заданий, обычный — до 30. |
| 2:00–2:40 | Результат: профиль навыков по темам, вероятность каждого грейда, категория | Итог — профиль по темам с погрешностью и категория: специализация на грейд. Не хватило уверенности — категории нет, а не выдуманная. Кандидат без истории ФСП получает нейтральную пометку, штрафа нет. |
| 2:40–3:10 | Выйти → «Войти через ФСП ID» → `fsp-winner` → достижения | Профиль связан с ФСП ID по OIDC. Достижения ФСП — самый весомый сигнал, но категорию они не меняют. |
| 3:10–3:50 | Окно работодателя: `employer@demo.example` → «Новая потребность» → вставить текст вакансии → разобрать | Работодатель описывает потребность словами, разбор виден по полям, неуверенные выделены. Разбирает правило или локальная модель, ранжирует модель никогда. |
| 3:50–4:30 | «Сформировать подборку» → карточка → «Почему этот кандидат» | Выдача идёт из категории теста: точный грейд, близкие, неподтверждённые ниже. У каждого есть соответствие и вероятность принятия, а объяснение раскладывает скор по темам, сумма вкладов равна скору. |
| 4:30–4:50 | Карточка кандидата, показать обезличенный вид | До принятия работодатель видит только обезличенную карточку: без ФИО, фото, возраста, вуза и контактов — это проверяется на бэкенде, а не в интерфейсе. |
| 4:50–5:20 | «Пригласить»: описание и вилка «от–до» в рублях, контакт → отправить | Вилка обязательна и указана в месяц до вычета НДФЛ. Недельный бюджет ограничивает отправку приглашений одной компанией; нагрузка на кандидата от всех компаний проверяется отдельно. |
| 5:20–5:50 | Окно кандидата: «Приглашения» → вилка видна до общения → «Принять» → сообщение | Кандидат видит условия до разговора. После принятия контакты раскрываются. |
| 5:50–6:00 | Окно работодателя: приглашение → ФИО, контакты, переписка | Контакты открылись только теперь. Отклик на вакансию работает так же, как дополнительный путь. Спасибо. |

## Запасные ходы

- Тест затянулся: сразу войти `devops-middle-fsp@demo.example` — категория и профиль готовы.
- Нет подборки: у демо-работодателя три потребности уже с подборками.
- ФСП ID не отвечает: Keycloak стартует около минуты; вход по email работает без него.

## Видео и покрытие сценария

Инвентаризация артефактов коммита `385a6ca` на 11 октября 2026: в
`docs/demo/recording/*/video.webm` шесть файлов общей длительностью **38,56 секунды**.
По метаданным `ffprobe` все содержат только видеопоток. Названия соответствуют следующим
тестам; таблица описывает код сценариев и наличие файлов, а не результат нового просмотра видео.

| Сценарий | Запись | Ограничение проверки по коду |
|---|---|---|
| Главная, тема и RU/EN | 4,64 с | Отдельный сценарий интерфейса |
| Регистрация и начало теста | 15,24 с | Только три ответа; завершение теста и получение нового профиля не проверяются |
| Вход через ФСП ID | 4,80 с | Привязка и достижения проверяются запросом API после входа |
| Просмотр готового профиля | 1,80 с | Используется заранее подготовленная учётка |
| Потребность, подборка, объяснение | 10,08 с | При недоступной кнопке построения используется сохранённая потребность; приглашение только открывается и закрывается |
| Скачивание PDF | 2,00 с | Проверяется событие скачивания и расширение файла |
| Принятие приглашения и контакты | Нет файла | Тест есть; приглашение создаётся через API, используются отдельные контексты без `recordVideo` |
| Отклик на вакансию | Нет файла | Тест есть; вакансия создаётся через API, отдельные контексты без `recordVideo` |

`frontend/playwright.demo.config.ts` задаёт Chrome, замедление 700 мс и запись для контекста
фикстуры. В тестах принятия приглашения и отклика используются ручные `browser.newContext()`
без настройки записи. Сохранённый `.last-run.json` содержит `passed` и пустой список ошибок,
но не содержит перечня тестов и SHA проверенного кода.

Для подтверждения полного маршрута остаётся пройти завершение теста новым кандидатом,
создание потребности и отправку приглашения через UI, затем принятие и раскрытие контактов
для той же пары. В тесте приглашения анонимность до согласия проверяется на другом кандидате;
проверку одной и той же пары до/после нужно подтвердить отдельно. При записи нужны оба
изолированных контекста. Код теста не заменяет журнал его успешного выполнения.

Короткие фрагменты не составляют ролик на 5–6 минут с речью. Сценарий такого ролика приведён
выше. Отсутствие расширения Chrome не блокирует имеющийся способ записи через Playwright;
озвучка и монтаж остаются отдельной работой.

Пересъёмка:

```
scripts/demo.sh up
cd frontend && E2E_BASE_URL=http://localhost:3100 E2E_MAILPIT_URL=http://localhost:8125 \
  npx playwright test -c playwright.demo.config.ts
```

Один раз нужен `npx playwright install ffmpeg` (кодек записи видео).
