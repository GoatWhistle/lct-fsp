# Механики подбора и тестирования

Что система делает, по каким формулам и почему именно так. Значения по умолчанию и имена
параметров конфига — в [parameters.md](parameters.md): здесь параметр назван по имени, а число
приведено, только когда без него непонятна мысль. Термины — [glossary.md](glossary.md), угрозы —
[threat-model.md](threat-model.md), проверка качества — [validation-plan.md](validation-plan.md).

## 1. Сквозная логика

**Кандидат.** Опрос → специализация. Сам выбирает грейд → адаптивный тест на этот грейд →
**оценка теста** → **категория** (специализация × грейд) по правилу уверенности. Параллельно
копится **профиль навыков**: уровень и погрешность по каждой теме, сведённые из всех сигналов с
весами уровней доверия.

**Работодатель.** Потребность → требования по темам → подборка: категория отсекает, внутри
порядок по P(соответствия) × P(принятия) с объяснением из самой формулы скора → приглашение с
вилкой из недельного бюджета → кандидат принимает → контакты и полный профиль раскрываются.

**Главный принцип.** Сигнал весит тем больше, чем труднее его подделать:

| Уровень доверия | Сигнал | Куда входит |
|---|---|---|
| 1 | Результаты ФСП — очные соревнования под надзором | профиль |
| 2 | Проверочный блок — короткий, на время, из невиданных семейств | категория и профиль |
| 3 | Адаптивный тест без надзора | категория и профиль |
| 4 | Регулярные задания от работодателей, оценка по рубрике | профиль |
| 5 | Самоописание — только стек | отдельное слагаемое скора с потолком |

Категорию определяет только тест (уровни 2–3): это ворота выдачи, и для всех они должны
измеряться одной сопоставимой процедурой. ФСП — самый весомый сигнал в профиле и ранжировании,
но на категорию не влияет, поэтому кандидат без ФСП ничего не теряет на входе в выдачу.

## 2. Справочники и шкала уровня

- **Справочники — данные, а не код:** специализации (MVP: бэкенд, фронтенд, данные/ML, QA,
  DevOps), грейды (стажёр, junior, middle, senior), темы каждой специализации, технологии стека
  со связью «технология → темы». Новая специализация добавляется данными.
- У темы в специализации есть вес $w_t$, $\sum_t w_t = 1$, по умолчанию равный. Он задаёт общий
  уровень (§3) и бланк теста (§6).
- **Шкала θ** — логиты IRT, общая для всех тем специализации. Грейду соответствует порог $c_g$
  (`grade_thresholds`: стажёр −1,5, junior −0,5, middle 0,5, senior 1,5): полосы грейдов шириной 1.
- **Экспертная сложность.** Эксперт относит семейство заданий к грейду, в середине полосы
  которого кандидат решает его в половине случаев: стартовая сложность $b_0$ — середина полосы
  (`expert_difficulty_by_grade`), стартовая разделяющая сила $a_0$ — `expert_discrimination`.
- Шкала не плывёт при калибровке: её держат якорные семейства с замороженными параметрами (§7).

## 3. Модель навыка — IRT 2PL

Вероятность верного ответа кандидата с уровнем $\theta_t$ по теме $t$ на семейство $f$:

$$P(u = 1 \mid \theta_t) = \sigma\big(a_f(\theta_t - b_f)\big), \qquad \sigma(x) = \frac{1}{1 + e^{-x}}$$

$b_f$ — сложность, $a_f$ — разделяющая сила; оба принадлежат семейству, а не экземпляру.

**Почему 2PL.** Модель Раша (1PL) считает все задания одинаково разделяющими, а «что выведет
код» и выбор из вариантов разделяют по-разному. 3PL добавляет параметр угадывания, который
плохо оценивается на сотнях ответов; угадывание гасим форматом: вычисляемый ответ или выбор с
перемешиванием из пяти и более вариантов.

**Иерархическое априорное.** Уровень по теме — общая часть плюс отклонение темы:

$$\theta_t = \theta_s + \delta_t, \qquad \theta_s \sim N(0, s_\theta^2), \qquad \delta_t \sim N(0, s_\delta^2)$$

$s_\theta$ — `theta_prior_sd`, $s_\delta$ — `topic_deviation_sd`.

На тему в тесте приходится 3–5 заданий. С независимым априорным по каждой теме оценки сильного
кандидата стягивались бы к нулю, то есть к junior, и senior не набирал бы уверенности. Общая
часть $\theta_s$ даёт темам занимать силу друг у друга: ответы по SQL кое-что говорят и о
бэкенде в целом.

**Обновление.** Совместное апостериорное $(\theta_s, \delta_1, \dots, \delta_T)$ приближается
нормальным $N(\mu, \Sigma)$ (приближение Лапласа). Наблюдения учитываются по порядку времени;
наблюдение $u$ по теме $t$ с весом $w$ сдвигает оценку так:

$$h = e_s + e_t, \quad p = \sigma\big(a(h^\top\mu - b)\big), \quad I = a^2 p(1-p)$$

$$\Sigma' = \Sigma - \frac{wI\,\Sigma h h^\top \Sigma}{1 + wI\,h^\top\Sigma h}, \qquad \mu' = \mu + w\,a\,(u - p)\,\Sigma' h$$

Это шаг Ньютона к моде, как в рейтинге Глико; для наблюдений с большой разделяющей силой
(достижения ФСП) шаг повторяется до сходимости моды. $w$ — вес уровня доверия: в оценке теста
$w = 1$, в профиле — по §11.

**Уровень по теме** — $\theta_t \sim N(h^\top\mu,\ h^\top\Sigma h)$: это «уровень и
погрешность» в профиле. **Общий уровень** по специализации — среднее по темам с весами
справочника:

$$\bar\theta = \sum_t w_t \theta_t \sim N(g^\top\mu,\ g^\top\Sigma g), \qquad g = e_s + \sum_t w_t e_t$$

Грейд решается по $\bar\theta$, а не по $\theta_s$ и не по правилу «каждая тема выше порога».
$\theta_s$ — уровень гипотетической «средней темы», и его погрешность упирается в предел при
любом числе заданий. Правило «каждая тема» превратило бы одну слабую тему в провал грейда и
удлинило тест. Специфику тем учитывает подбор: потребность сама говорит, какие темы важны (§12).

**Оценка — чистая функция:** (априорное, упорядоченные наблюдения, момент запроса) →
$(\mu, \Sigma)$. Без БД и состояния, детерминирована, покрывается юнит-тестами и проверками свойств:
больше верных ответов — выше уровень, больше заданий — меньше погрешность.

## 4. Категория и правило уверенности

Категория — специализация из опроса × грейд из теста. Грейд $g$ присваивается, когда

$$P(\bar\theta \ge c_g) = \Phi\!\left(\frac{\bar\mu - c_g}{\bar\sigma}\right) \ge \gamma$$

где $\gamma$ — порог уверенности `grade_confidence` (по умолчанию 0,8), а $\bar\mu, \bar\sigma$ —
по **оценке теста**: только наблюдения теста и проверочного блока, $w = 1$.

**Почему уверенность, а не процент верных.** Процент зависит от того, какие задания достались: в
адаптивном тесте и сильный, и слабый решают примерно половину своих заданий. Правило уверенности
ограничивает завышение: присваивая грейд, система допускает не больше 20 % вероятности по модели,
что кандидат ниже порога. Цена — занижение у тех, кто у нижней границы полосы; они видят «между
junior и middle» и могут пересдать.

**Первичное определение — каскад вниз.** Тест на заявленный грейд $g$. Если правило не
выполнено, сразу предлагается $g-1$. Дотест продолжает ту же оценку: прошлые ответы — наблюдения
того же уровня. Если уверенность для $g-1$ уже набрана, грейд присваивается без дотеста. Не
прошёл стажёра — кандидат остаётся без категории, повтор через `no_category_retest_days`. Каскад
— одно определение, интервал смены грейда на него не действует.

**Смена грейда.** Попытка на грейд выше или ниже — отдельное измерение с чистого листа:
априорное без прошлых попыток, чтобы категория каждого кандидата опиралась на одну сопоставимую
процедуру (профиль при этом копит все попытки). Категория меняется, только если правило
выполнено; проваленная попытка категорию не меняет, принудительного понижения нет. Попытки — не
чаще `grade_change_interval_days` от последней попытки, удачной или нет: иначе повторы
превращаются в лотерею «рано или поздно повезёт» и в сбор банка заданий.

**Подсказка «попробуйте грейд выше»** — когда $P(\bar\theta \ge c_{g+1}) \ge$
`grade_up_hint_confidence`.

**Язык уверенности.** Вероятности полос $\pi_g = P(c_g \le \bar\theta < c_{g+1})$: «уверенно
middle», если $\pi_g \ge 0{,}8$; иначе «между junior и middle» — два соседних грейда с наибольшей
суммой. Категория и словесный уровень могут различаться: «категория middle, уровень между middle
и senior» — честное описание кандидата у верхней границы.

## 5. Семейства заданий

**Семейство** — шаблон, генератор параметров и проверка ответа кодом. **Экземпляр** — шаблон с
конкретными параметрами; seed экземпляра хранится в предъявлении, экземпляр воспроизводим.

Форматы:

- **вычисляемый ответ** — что выведет код, результат SQL-запроса, состояние после трассировки;
- **выбор с перемешиванием** — варианты генерируются из параметров, неверные варианты —
  типичные ошибки;
- **короткая задача с автопроверкой** — функция, которую проверяют тесты.

Требования к семейству при попадании в банк:

1. Эталон вычисляется исполнением кода, а не хранится текстом; ответ проверяет бэкенд,
   правильные ответы на фронт не уходят.
2. Верные ответы двух случайных экземпляров совпадают с вероятностью не выше
   `family_answer_collision_max`: утёкший ответ не подходит к чужому экземпляру.
3. **Однородность:** разброс сложности по группам параметров не выше
   `family_instance_difficulty_sd_max`, иначе семейство делится (например, «с рекурсией» и «без»).
   Так экземпляры одного семейства сопоставимы по сложности, и это проверяется данными — по
   остаткам модели в группах параметров.
4. В банке не меньше `bank_min_families_per_topic` семейств на тему и не меньше
   `bank_min_families_per_grade` на каждый грейд темы, из них `anchor_families_per_topic` якорных.
   Без заданий нужной трудности тест не набирает точности у краёв шкалы и упирается в лимит
   заданий.

**LLM — только офлайн для черновиков шаблонов.** В банк шаблон попадает после ревью человеком и
автопроверки: генератор, эталон, коллизии ответов. Задания под каждого кандидата LLM не
генерирует: сложность одноразового задания неизвестна, и калибровать его не на чем. Параметры
семейства оцениваются на всех его экземплярах.

## 6. Адаптивный тест

**Бланк** — веса тем и ограничения покрытия. Для теста на категорию веса — $w_t$ специализации;
для превью теста по вакансии — веса тем потребности (§12), движок тот же. Каждая тема получает
не меньше `test_min_items_per_topic` заданий и не больше доли `test_max_topic_share` от длины.

**Старт.** Задания выбираются по той же чистой функции оценки, но с априорным средним в пороге
заявленного грейда: тест сразу начинается с заданий нужного уровня. Сама оценка, по которой
решается грейд, считается с общим априорным. Заявленный грейд влияет только на выбор заданий и
никогда на оценку — иначе заявивший senior получал бы фору.

**Шаг.**

1. **Тема.** Сначала недобранные минимумы покрытия. Иначе — тема с наибольшим вкладом в
   погрешность общего уровня $w_t^2\sigma_t^2$ среди тем, не упёршихся в потолок доли.
2. **Кандидаты:** семейства темы, кроме скомпрометированных, уже виденных кандидатом в любой
   его попытке и превысивших потолок показов.
3. **Информация** при текущей оценке темы: $I_f(\mu_t) = a_f^2\,p(1-p)$.
4. **Случайный выбор** из `exposure_top_k` самых информативных — каждый получает свой набор.
5. **Новый экземпляр** со свежим seed.

**Потолок показов.** Доля попыток за окно последних `exposure_window_attempts` попыток по
специализации, в которых показано семейство, не выше `exposure_max_rate`. Если в теме под
потолком ничего не осталось, берётся наименее показанное семейство, событие пишется в лог — это
сигнал, что банк темы мал. Потолок осмыслен, только когда семейств хватает: средняя доля показов
— примерно $n_t / N_t$ (заданий темы в тесте на семейства темы в банке). При четырёх заданиях
темы на тест и десяти семействах средняя доля 0,4, и потолок 0,5 срезает только «любимчиков».
Главный рычаг — рост банка: при двадцати семействах на тему потолок можно опустить до 0,25.

**Остановка:** $\bar\sigma \le$ `test_stop_sd`, задано не меньше `test_min_items` и выполнены
минимумы покрытия — либо достигнут `test_max_items`. Остановка по точности уравнивает точность,
а не длину: сильный и слабый кандидат заканчивают с одинаковой погрешностью.

**Восстановление.** Состояние попытки — список предъявлений, оценка — чистая функция от него:
прерванная попытка восстанавливается пересчётом после перезапуска бэкенда.

**Предъявление хранится целиком:** попытка, семейство, seed и параметры экземпляра, ответ,
верность, время ответа по часам сервера (клиентские часы подделываются), оценка темы до ответа
$(\mu_t, \sigma_t)$, события вставки и потери фокуса, если кандидат дал согласие. На этих записях
стоят калибровка, защита теста и валидация.

**Блок по теме** — короткий адаптивный тест по одной теме из `topic_block_items` заданий, не
чаще `topic_block_interval_days` на тему. Наблюдения идут в профиль с весом теста, категорию блок
не меняет. Это действие из подсказок «что поднимет выше» (§15).

## 7. Калибровка по Эло

**Старт** — экспертные $a_0$, $b_0$. **После каждого ответа** кандидат «играет» против
семейства, сложность обновляется онлайн:

$$p = \sigma\!\left(\frac{a_f(\mu_t - b_f)}{\sqrt{1 + \pi a_f^2 \sigma_t^2 / 8}}\right), \qquad b_f \leftarrow b_f - K_n\,(u - p)$$

$$K_n = \max\!\left(K_{\min},\ K_0\,\frac{n_0}{n_0 + n}\right)$$

$K_0$ — `elo_k_initial`, $K_{\min}$ — `elo_k_min`, $n_0$ — `elo_k_half_responses`, $n$ — число
ответов на семейство, $(\mu_t, \sigma_t)$ — оценка кандидата по теме до ответа.
Знаменатель внутри $\sigma$ учитывает погрешность кандидата, как в Глико: ответ кандидата с
неточной оценкой двигает сложность меньше. Перевод в IRT прямой: шкала Эло здесь — сразу логиты
θ, и $b_f$ — та же сложность 2PL.

**Разделяющая сила** онлайн не обновляется: слишком шумно. Когда у семейства набирается
`calibration_refit_min_responses` ответов, $(a_f, b_f)$ переоцениваются пакетно — логистической
регрессией ответов на итоговые оценки кандидатов со штрафом к экспертным значениям.

**Якорные семейства** — по `anchor_families_per_topic` на тему с замороженными параметрами. Они
держат начало и масштаб шкалы. Без якорей совместная калибровка кандидатов и заданий может
уплыть целиком, и пороги грейдов потеряют смысл.

**Опорные параметры для детектора дрейфа.** После `calibration_reference_freeze_responses`
ответов $(a_f, b_f)$ замораживаются как опорные. Эло продолжает с малым шагом, но дрейф (§8)
меряется от опорных — иначе калибровка «съела» бы утечку, приняв её за то, что семейство просто
легче.

**Почему Эло:** онлайн, O(1) на ответ, работает с первого ответа, без пакетного переобучения;
проверенный подход адаптивных обучающих систем (Pelánek, 2016).

## 8. Защита теста

**Детектор дрейфа** — risk-adjusted Bernoulli CUSUM (Steiner и др., 2000) по каждому семейству.
На каждый ответ:

$$p_0 = \sigma\big(a(\hat\theta - b)\big), \quad p_1 = \sigma\big(a(\hat\theta - b + \Delta)\big), \quad W = \begin{cases}\ln(p_1/p_0), & u = 1\\ \ln\big((1-p_1)/(1-p_0)\big), & u = 0\end{cases}$$

$$S \leftarrow \max(0,\ S + W)$$

Когда $S$ превышает `drift_cusum_h`, семейство помечается скомпрометированным. $a, b$ — опорные
параметры, $\hat\theta$ — оценка кандидата по теме до ответа, $\Delta$ —
`drift_shift`: насколько легче становится слитое семейство. Поправка на уровень отвечавших
встроена: семейство, которое чаще решают просто более сильные кандидаты, тревоги не поднимает.
Скомпрометированное семейство выводится из выдачи, банк получает задачу на замену, ответы на него
в незавершённых попытках выпадают из оценки. Уже присвоенные категории автоматически не
пересматриваются.

**Модель времени ответа** — логнормальная (van der Linden, 2006). По семейству $\ln T$ верных
ответов $\sim N(m_f, s_f^2)$, оценка робастная (медиана, MAD), после `rt_min_responses` ответов.
Флаг предъявления: ответ верный, задание трудное для кандидата ($p \le$ `rt_hard_item_p` по
оценке до ответа) и $(\ln T - m_f)/s_f \le -$`rt_fast_z`. Время — по серверу.

**События вставки и потери фокуса** пишутся только с согласия кандидата, только как счётчики и
только как сигнал подозрения. Без согласия тест проходится так же.

**Подозрительный результат** — попытка, которая повышает категорию или присваивает её впервые,
плюс хотя бы одно: флагов времени не меньше `rt_flags_for_verification`, событий вставки и
фокуса не меньше `focus_events_for_verification`. Попытку, которая категорию не повышает, не
проверяют: защищать нечего.

**Проверочный блок** — `verification_items` заданий из невиданных кандидатом семейств тех же
тем, на время: `verification_time_limit_minutes` на блок, неотвеченное к сроку считается
неверным. Сложность подобрана так, чтобы при уровне основного теста вероятность верного ответа
была около `verification_target_p`: так блок чувствительнее всего к завышению на грейд.

Сравнение — проверка согласия. По оценке основного теста ожидаем $E = \sum_i p_i$ верных с
дисперсией $V = \sum_i p_i(1-p_i)$ плюс вклад погрешности основной оценки (дельта-метод);
$z = (X - E)/\sqrt{V}$, где $X$ — число верных.

- $z \ge -$`verification_mismatch_z` — **совпал**: категория присваивается по результату попытки,
  наблюдения блока входят в профиль с весом проверочного блока, в профиле пометка «уровень
  подтверждён».
- Иначе — **расхождение**: попытка категорию не повышает, её наблюдения не входят ни в оценку,
  ни в профиль (наблюдения самого блока входят). Кандидат видит причину — «по основному тесту
  ожидалось около 7 верных из 10, получено 2» — и может пройти блок снова через
  `verification_retest_days`.

Сравнение идёт через ожидаемое число верных, а не через две оценки уровня: оценка короткого
блока сильно стянута к априорному и систематически занижала бы сильных честных кандидатов.

**Честно об ограничениях.** По модели десять заданий ловят завышение на два грейда почти всегда,
а на один — примерно в половине случаев; эксперимент это проверит. Против утечки блок силён:
невиданные семейства обнуляют выгоду от слитого банка. Против LLM-помощника слаб: модель решает
и невиданные задания, а время помогает, только если помощь медленная. Блок — облегчённая замена
прокторинга: он поднимает цену обмана, но не исключает его. Высший уровень доверия — ФСП.

Кандидат может пройти проверочный блок и добровольно, чтобы подтвердить уровень, — например, по
рекомендации при расхождении с ФСП (§11).

**Флаг сам по себе категорию не понижает** и работодателю не показывается. Работодатель видит
только положительную пометку «подтверждено проверочным блоком».

## 9. Почему тест устойчив к распространению заданий

ТЗ отвергает два подхода: единый набор заданий разойдётся, а генерация уникальных заданий
нейросетью не гарантирует сопоставимой сложности. Мы генерируем экземпляры из шаблонов с
откалиброванными параметрами семейства, и защита многослойная:

1. **Утёкший экземпляр бесполезен.** Параметры у каждого свои, ответ вычисляется, совпадение
   верных ответов двух экземпляров ограничено `family_answer_collision_max`.
2. **Утёкшее семейство помогает частично и недолго.** Знать тип задания — не то же, что знать
   ответ. Адаптивный выбор, случайность среди топ-k и потолок показов дают каждому малую долю
   банка. Детектор дрейфа замечает семейство, которое решают чаще ожидаемого по уровню
   отвечавших, и выводит его.
3. **Слить весь банк дорого.** Попытки ограничены интервалом, шаблоны и генераторы живут только
   на бэкенде, банк растёт.
4. **Обман неподнадзорного теста упирается в уровни доверия.** Подозрительное повышение категории
   проходит через проверочный блок, а в ранжировании выше стоит ФСП, который не сгенерируешь.
5. **Это измеряется:** кривая атаки утечкой 10 / 30 / 50 % банка для трёх схем теста и точность
   детектора — метрики M14 и M15 [плана валидации](validation-plan.md).

## 10. Почему результаты сопоставимы

1. **IRT учитывает сложность доставшихся заданий:** уровни двух кандидатов, решавших разные
   задания, лежат на одной шкале.
2. **Параметры принадлежат семейству** и оценены на всех его экземплярах; однородность
   экземпляров проверяется (§5).
3. **Якорные семейства** держат шкалу во времени — пороги грейдов не плывут.
4. **Остановка по точности и одно правило уверенности** — у всех одинаковая погрешность на
   финише и одинаковый критерий присвоения.
5. **Это измеряется:** стабильность грейда при повторном прохождении, сходимость калибровки,
   совпадение с истиной — метрики M9, M12, M10.

## 11. Профиль навыков и уровни доверия

**Две оценки на одной модели.** Оценка теста решает категорию (§4). Профиль навыков питает
подбор, карточку и обратную связь: те же $\theta_t$ на той же шкале, но в него входят наблюдения
всех уровней доверия.

**Вес уровня доверия — степень правдоподобия.** Наблюдение с весом $w$ даёт $w \cdot I$
информации; это единый механизм для разнородных сигналов. Вес читается как «сколько стоит одно
наблюдение этого уровня в наблюдениях полного доверия»: чем легче подделать сигнал, тем меньше он
сужает погрешность.

| Уровень | Как становится наблюдением | Вес |
|---|---|---|
| ФСП | Достижение — «решённое задание» сложности $b$ = уровень результата (`fsp_result_difficulty`) и разделяющей силы `fsp_result_discrimination` по темам дисциплины, а в командном зачёте — по темам роли в команде | `trust_weight_fsp` |
| Проверочный блок | IRT-наблюдения, как в тесте | `trust_weight_verification` |
| Адаптивный тест, блок по теме | IRT-наблюдения | `trust_weight_test` |
| Регулярное задание | Оценка по рубрике 0–3 — три ступени: $r \ge 1$, $r \ge 2$, $r = 3$; каждая — бинарное наблюдение по темам задания со сложностью $c_g$ грейда категории плюс смещение `regular_task_rubric_offsets` и разделяющей силой `regular_task_discrimination` | `trust_weight_regular_task` |
| Самоописание | В θ не входит; только стек, отдельное слагаемое скора не больше `self_reported_stack_cap` (§12); на категорию не влияет | — |

**ФСП — одностороннее свидетельство.**
$P(\mathrm{result} \mid \theta) = \sigma\big(a(\theta - b)\big)$: сильный результат поднимает
оценку, если она ниже, и почти не влияет, если оценка уже выше. Участие без призового места — факт в
профиле, а не наблюдение: плохой день на соревновании говорит о навыке меньше, чем хороший. Уровни
результатов — стартовые экспертные; они уточняются, когда у кандидатов накопятся и ФСП, и тест.

**Регулярное задание** работодатель создаёт для категории; система предлагает его кандидатам
категории, каждому не чаще `regular_task_interval_days`. Кандидат решает задачу или описывает
подход, автор задания оценивает ответ по рубрике: 0 — не решено или не по делу; 1 — частично,
подход с ошибками; 2 — верно в целом; 3 — верно и хорошо: оптимально, с разбором краёв.

**Свежесть.** Между наблюдениями к $\Sigma$ добавляется шум $Q\,\Delta t$: погрешность растёт так,
что дисперсия прибавляет `profile_decay_sd_per_year`² за год, но не выше априорной. Без новых
сигналов уверенность в выдаче падает сама; если последний сигнал старше `profile_stale_days`, в
объяснении — «давно не подтверждал уровень». Оценка теста и категория не устаревают и меняются
только попыткой смены грейда.

**Кандидат без ФСП** — полноценный кандидат: в профиле нейтральная пометка «нет истории ФСП»,
профиль — ровно то, что дают его собственные сигналы, как при выключенном модуле ФСП. ФСП не
сдвигает чужие скоры. Меняется только относительный порядок: кандидат с подтверждённым
результатом поднимается выше, как и требует ТЗ.

**Расхождение ФСП и теста.** Если по теме, сопоставленной дисциплине, оценка теста ниже уровня
результата ФСП больше чем на `fsp_divergence_theta`, — пометка и рекомендация проверочного блока.
Профиль считается как обычно, штрафа нет. Тест выше результата ФСП расхождением не считается:
результат ФСП — нижняя граница.

**Кандидат видит свой профиль:** уровень по темам словами, погрешность, из каких сигналов он
сложился и что из этого видит работодатель.

## 12. Подбор

**Категория отсекает.** В подборку попадают только кандидаты с категорией, присвоенной тестом:
точные — специализация и грейд потребности; «близкие» — та же специализация и грейд на
`nearby_grade_distance` от грейда потребности, отдельным блоком. Кандидат без категории или без
согласия на публикацию в выдачу не попадает.

**Требования.** Потребность → темы специализации с важностью: ключевая, важная, желательная. По
умолчанию важность выводится из стека: тема, с которой связано не меньше
`need_key_topic_min_technologies` технологий потребности, — ключевая; одна технология — важная;
ни одной — желательная. Работодатель правит важность чипсами. Вес темы $v_t$ — вес её важности
(`need_importance_weights`), нормированный на сумму. Требуемый уровень по каждой теме — порог
грейда потребности: $\mathrm{req}_t = c_g$. Одно требование на грейд легко объяснить
работодателю и не плодит произвольных надбавок; важность выражается весом.

**Скор соответствия:**

$$S = (1 - \lambda)\sum_t v_t\,P(\theta_t \ge \mathrm{req}_t) + \lambda\,o, \qquad P(\theta_t \ge \mathrm{req}_t) = \Phi\!\left(\frac{\mu_t - \mathrm{req}_t}{\sigma_t}\right)$$

$\mu_t, \sigma_t$ — из профиля навыков; $\lambda$ — `self_reported_stack_cap`; $o$ — доля
технологий потребности в самоописанном стеке кандидата. По линейности ожидания первое слагаемое
— ожидаемая взвешенная доля выполненных требований. В интерфейсе это «соответствие N %»;
вероятности по темам откалиброваны и проверяются как вероятности (M4). Самоописание поднимает
скор не больше чем на $\lambda$, как бы кандидат ни переписал резюме.

**Объяснение — это и есть скор.** Вклад темы — $(1-\lambda)\,v_t\,P(\theta_t \ge \mathrm{req}_t)$,
вклад стека — $\lambda o$. Сумма вкладов равна скору, обнуление фактора уменьшает скор ровно на его
вклад: объяснение не пишется задним числом.

Формулировки — язык уверенности (`confidence_language_bands`):

- $P \ge 0{,}8$ — «уверенно выше требования»;
- $0{,}5$–$0{,}8$ — «скорее выше»;
- $0{,}2$–$0{,}5$ — «скорее ниже»;
- ниже $0{,}2$ — «ниже требования»;
- $\sigma_t >$ `topic_low_data_sd` — «данных мало».

Рядом — источник уверенности: «подтверждено ФСП», «подтверждено проверочным блоком», «давно не
подтверждал уровень».

**Монотонность:** $\partial S/\partial\mu_t \ge 0$ — рост уровня по нужной теме не опускает
кандидата. Сужение погрешности поднимает того, кто выше требования, и опускает того, кто ниже:
уверенность, что требование не выполнено, — тоже уверенность.

**Порядок** — по взаимному скору (§13), с переключателем «только соответствие». Ничьи
разрешаются детерминированно по хэшу пары «подборка — кандидат», а не по защищённым признакам и
не по дате регистрации.

**Подборка — объект:** снимок потребности, выдача на момент построения со скорами и вкладами,
шортлист. Позже она открывается с той же выдачей. Фильтры применяются поверх и её не
перезаписывают, сброс возвращает исходный порядок; перестроение создаёт новую подборку.

**Поиск по банку** — те же обезличенные карточки и фильтры: специализация, грейд, категория, стек,
подтверждённые достижения ФСП, уверенность в уровне (погрешность общего уровня по профилю не выше
`search_confident_sd`). Без потребности внутри категории порядок — по $P(\bar\theta \ge c_g)$ по
профилю: выше те, в чьём уровне система увереннее. Это и есть «сила подтверждённого профиля» из ТЗ.

**Разбор потребности из текста** — локально: правила, словарь синонимов, при желании локальная
модель. Экран «система поняла так» с правкой. Вне справочника — честный ответ «такой
специализации нет» и ближайшие категории. Текст во внешние API не уходит.

## 13. Взаимный скор и модель принятия

**Порядок подборки** — $S \times P_{\mathrm{accept}}$. Работодателю мало подходящего кандидата,
нужен тот, кто скажет «да», а лучшим кандидатам не нужны полсотни приглашений, которые они не
примут.

**P(принятия)** — классификатор CatBoost. Признаки:

- вилка относительно ожиданий кандидата и рыночной вилки категории;
- грейд;
- совпадение формата работы и города с учётом готовности к переезду;
- загрузка кандидата открытыми приглашениями;
- активность — дни с последнего входа;
- соответствие $S$.

Защищённых признаков нет. **Монотонные ограничения:** выше вилка — вероятность не ниже; больше
открытых приглашений — не выше. **Объяснение** — SHAP, точно аддитивный в логит-пространстве
модели.

**Обучение** — на поведении синтетических кандидатов из симулятора; метки для дообучения на
реальных данных — статусы приглашений и откликов: принято — 1, отклонено и истекло — 0. Без
файла модели множитель равен 1, и подборка работает по одному соответствию.

**Подсказка по вилке:** вероятность принятия при текущей вилке и вилка, при которой она достигает
`acceptance_target_probability`. Монотонность гарантирует единственный порог, его находит поиск
по сетке. Ожидаемая зарплата кандидата работодателю не показывается, а подсказка округляется до
`salary_hint_rounding_rub`, чтобы не выдавать ожидание точно.

## 14. Рынок

- **Вилка «от–до» в рублях** обязательна в приглашении и вакансии: обе границы больше нуля,
  «от» не больше «до».
- **Бюджет приглашений** — `invitation_weekly_budget` на компанию за календарную неделю, с
  понедельника 00:00 по Москве. Отклонённые и истёкшие приглашения в бюджет не возвращаются:
  иначе каждый отказ освобождал бы место для следующего приглашения, и бюджет перестал бы
  ограничивать рассылку. Отклики на бюджет не влияют.
- **Одно открытое приглашение** компании кандидату: следующее — после закрытия прошлого.
- **Срок ответа** — `invitation_ttl_days`, потом «истекло».
- **Статусы:** отправлено → просмотрено → принято, отклонено или истекло. Переходы проверяет
  бэкенд.
- **Обезличенная карточка** — до принятия приглашения или собственного отклика: без ФИО, фото,
  возраста, вуза и контактов. Свободный текст «о себе» до раскрытия не показывается — в нём
  бывают имя и контакты. Достижения ФСП везде показываются как подтверждённые, отдельно от
  самоописания; в карточке они обобщены: уровень результата, дисциплина, год
  — без названия мероприятия и места, потому что таблицы результатов публичны, и по точному
  мероприятию с местом человека находят по фамилии.
- **Раскрытие** контактов и полного профиля — только компании, чьё приглашение принято или на
  чью вакансию кандидат откликнулся. Проверяется на бэкенде на каждом эндпоинте, отдающем данные
  кандидата.

## 15. Обратная связь кандидату

- **Агрегаты** за `feedback_period_days`: в скольких подборках был кандидат и медианное место.
  Показываются, только если подборок не меньше `feedback_min_selections`, без работодателей и
  их потребностей.
- **Что поднимет выше** — контрфактически той же функцией скора. По встреченным потребностям
  считаем прирост $S$ от сужения погрешности темы (как после блока по теме) и от роста уровня на
  полосу. Показываем темы с наибольшим приростом, у каждой — действие: пройти блок по теме,
  привязать ФСП ID, ответить на регулярное задание.

## 16. LLM и персональные данные

- **LLM не ставит оценок и не ранжирует.** Допустимые места — офлайн-черновики шаблонов заданий
  (с ревью человеком) и базовая линия «LLM-ранжировщик» на стенде валидации (локальная модель,
  синтетические данные).
- **Персональные данные во внешние API не уходят:** резюме и потребности разбираются локально.
- **Текст из PDF очищается** от скрытого текста (белого, нулевого размера, за полями страницы) и
  инструкций. Распознанное попадает только в самоописание — низший уровень доверия.

## 17. Защищённые признаки

Пол, возраст и вуз не входят ни в одну модель: ни в оценку уровня, ни в скор соответствия, ни в
P(принятия). Список признаков каждой модели проверяется тестом. В карточке до раскрытия их нет.
