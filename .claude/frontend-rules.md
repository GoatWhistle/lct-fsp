## 3. Устройство

Приложение — кабинеты двух ролей с роутингом, поэтому раскладка FSD по образцу rlt, а не слои did. [предл.]

```text
src/
  app/          провайдеры, роутер (routes/*-routes.ts по ролям и владельцам), guards, shell
  pages/        экран = композиция фич и слотов, без своей логики; папка на страницу
  features/     сценарии: test-session, need-editor, selection-board, invite, candidate-search,
                candidate-card, conversation, profile, employer-invitations, vacancy-editor, …
  entities/     данные и их отображение: запросы (*.queries.ts), measure (GradeRuler, MatchScore,
                TrustBadge), catalog, session, need, selection, invitation, vacancy, task, …
  shared/
    api/        клиент, schema.gen.ts, types.ts, ApiError, anonymousId
    ui/         примитивы по группам: brand, data-display, forms, layout, overlays, primitives, states
    motion/     Swap, usePresence, withViewTransition, staggerStyle, motionMs
    i18n/       словари locales/{ru,en}/<namespace>.json, resources.ts (npm run i18n:sync), форматтеры
    hooks/      useMediaQuery, useStoredFlag, useOnline
    styles/     global.css, reset.css, tokens/*, compose/layout/rows/control/choice.module.css
```

- Импорты только вниз: `app → pages → features → entities → shared`. Соседи одного слоя друг друга не
  импортируют: связка фич — через пропсы и слоты на странице (`invite={(entry) => <InviteAction …/>}`). [утв.]
- Компонент — папка `kebab-case/` с `name.tsx` и `name.module.css` (раскладка GoatWhistle); у фичи и
  сущности `index.ts` с именованными экспортами; хуки — `use-xxx.ts`. [утв.]
- Пропсы — `readonly`-интерфейс `XxxProps`. Варианты — карта `Record<Variant, string>`. [предл.]
- Повторяющийся блок — компонент в `shared/ui` или `entities`, не копия разметки. [утв.]
- Новый экран собирается из тех же примитивов, что соседние. Самодельный аналог примитива запрещён. [предл.]
- Логику и проверки прав держит бэкенд. Фронт не решает, что показать работодателю из контактов
  кандидата: скрытое просто не приходит (`AGENTS.md`). [утв. проектом]

## 4. Тексты и языки

**[утв.]** Два языка, RU и EN, все тексты интерфейса — из словарей, как в rlt. RU — по умолчанию.

Устройство по rlt-hack-deploy `frontend/src/shared/i18n/` и did_hack `frontend/src/ui/shared/i18n/` [предл.]:

- словари `shared/i18n/locales/{ru,en}/<ns>.json`, неймспейсы по фичам: `common`, `auth`,
  `candidate`, `test`, `profile`, `employer`, `selection`, `invitation`, `vacancy`, `errors`;
- ключ всегда полный `ns:path`, английский; `resources.ts` с `satisfies`, `i18next.d.ts` выводит тип
  ключей из `en` — опечатка ломает typecheck; тест проверяет одинаковый набор ключей в ru и en;
- `LocaleProvider`: сохранённый выбор (`localStorage`, в try/catch), иначе `navigator.languages`, иначе
  ru; ставит `<html lang>` и заголовок вкладки из `common:app.documentTitle`;
- переключатель — фича `locale-switch`, как в rlt: квадратная кнопка с глобусом в шапке → `Menu` с
  флагом, названием на своём языке (`lang`) и галочкой; меню закрывается через `settleDelay`; текст
  интерфейса меняется сразу, анимируются меню и индикатор выбора [утв.];
- числа, проценты, даты, деньги — через `Intl` по локали (`useFormatters`), в сообщениях
  `{{x, number}}`, перечисления — `list`. Склейки строк из чисел нет;
- зарплата — всегда «от–до», в рублях, в месяц до вычета НДФЛ, и это подписано на обоих языках
  (`AGENTS.md`); формат вилки — один компонент `entities/salary`;
- модель не хранит фраз (interrao): маппинги статусов и стадий — `Record<Status, MessageKey>`;
  нынешние `words.ts` переезжают в словари;
- ошибки: бэкенд отдаёт `{ code, message }`. Показывается `errors:api.<code>`, при отсутствии ключа —
  `errors:kind.<kind>`; `message` бэкенда в интерфейс не попадает;
- кириллица — только в `locales/`; литеральный текст в JSX и в `aria-label`, `title`, `placeholder`
  запрещён (проверки `cyrillic`, `jsx-text`); ожидаемый текст в тестах — через словарь;
- **[утв.] Без длинных тире и точек-разделителей.** «Бэкенд · middle», «компания — вилка — срок» —
  паттерн ИИ-генерации. Несколько атрибутов — отдельные элементы с иконкой и `gap`, колонки сетки
  или пары «подпись / значение»; пояснение — отдельное предложение, двоеточие или скобки; диапазон —
  «от … до …». Короткое `–` допустимо только внутри числового диапазона (`10–20`). Касается словарей
  обоих языков, PDF и писем. Проверки `dot-separators` (из rlt) и `dash-separators` по `locales/`
  и JSX: ` — `, ` – `, ` · `, ` • `, ` | ` как разделитель.

**[утв.]** Английская версия — полностью английская: «ФСП» → «FSP», «Федерация спортивного
программирования» → «Federation of Sports Programming of Russia», названия грейдов, специализаций, статусов,
сфер — всё переводится. Картинки и логотипы с русским текстом имеют английскую версию
(`public/brand/<name>.ru.svg` / `.en.svg`), компонент `BrandAsset` выбирает по локали; одинаковые
для обоих языков ассеты (знак-сеть, карта) — без суффикса. Аббревиатура ФСП в ключах словаря —
`common:brand.short` / `common:brand.full`, литералом нигде.

Данные бэкенда не переводятся и выводятся с `lang` своего языка через `<BackendText>`: тексты LLM
(разбор потребности, пересказ подборки, чат), текст заданий теста, описание вакансии, сообщения
переписки, самоописание кандидата. [утв. в did_hack, переносится] Справочники — [вопрос 1].

## 5. Анимации

**[утв.]** Анимировано всё: у каждого типа элемента есть заданное поведение, включая открытие и закрытие
всего всплывающего и раскрывающегося. Скилы — `.claude/skills/`: `emil-design-eng`, `review-animations`
(+ `STANDARDS.md`), `improve-animations`, `find-animation-opportunities`, `animation-vocabulary`.

### 5.1 Общие правила [предл.]

- Анимируются только `transform`, `opacity`, `clip-path`, `filter: blur` ≤ 2px. Запрещены `width`/`height`,
  `transition: all`, `ease-in`, `scale(0)`; вход — от `scale(0.95)` + `opacity: 0`.
- UI-анимации короче 300ms, выход быстрее входа, без bounce.
- Литеральные ms и кривые — только в `tokens/motion.css`, keyframes — в `tokens/keyframes.css`,
  компонент берёт их через `--motion-*`. В TS нет чисел-миллисекунд: `motionMs("--dur-base")`.
- Hover — только в `@media (hover: hover) and (pointer: fine)`. Фокус не анимируется, один общий
  `:focus-visible`. Действия с клавиатуры не анимируются (`useInputModality`).
- Не анимируются: пагинация, прокрутка к элементу, данные из кэша, смена цвета (её не гейтит reduced motion).
- FLIP прерываемый: новый переезд начинается от видимого положения. После загрузки шрифтов индикаторы
  перемеряются без анимации.
- Скелет — через 200ms, держится не меньше 300ms; содержимое проявляется, только если скелет реально
  был виден. Спиннер — через 400ms. При наличии данных — затемнение `stale`.

Токены движения — как в did_hack `tokens/motion.css` (кривые дословно из скилов):
`--ease-out` `cubic-bezier(0.23, 1, 0.32, 1)`, `--ease-in-out` `cubic-bezier(0.77, 0, 0.175, 1)`,
`--ease-drawer` `cubic-bezier(0.32, 0.72, 0, 1)`; `--dur-instant` 80, `--dur-press` 140, `--dur-fast` 160,
`--dur-fast-exit` 110, `--dur-base` 200, `--dur-exit` 140, `--dur-panel` 260, `--dur-slow` 320,
`--dur-draw` 900; `--stagger` 40ms, `--press-scale` 0.97, `--press-scale-surface` 0.99.

### 5.2 Что и как анимируется у нас [предл.]

| Элемент | Анимация |
| --- | --- |
| Кнопки, карточки-ссылки | hover `--transition-control`; `:active` scale 0.97 / 0.99; в `pending` не сжимается, подпись и `pendingLabel` в одной ячейке грида, ширина постоянна, `aria-busy` |
| Смена экрана в кабинете | `withViewTransition` с лимитом 900ms; без поддержки или при reduced motion — сразу |
| Первая загрузка экрана | карточки лесенкой `--motion-slide-in`, задержка `calc(var(--i) * var(--stagger))` |
| Путь к категории: Опрос → Грейд → Тест → Категория | индикатор шага переезжает по transform, пройденный шаг получает отметку `pop-in`, содержимое шага — `Swap` |
| Тест: следующее задание | `Swap`: старое уходит, новое входит; высота фиксируется на смену. Выбор ответа — точка радио opacity + scale |
| Итог теста: уровень ± погрешность, вероятности грейдов | полосы `scaleX` от нуля, лесенкой; интервал погрешности проявляется после полосы; категория — `rise-in`. Только при первом показе, не из кэша |
| Профиль навыков по темам | то же, что у итога; бейдж доверия («подтверждено ФСП») — `pop-in` |
| Подборка | строки лесенкой при построении; «Показать ещё» добавляет без лесенки у старых строк; «Перестроить» — `Swap` списка; разделитель нижнего блока (неподтверждённый грейд) — `slide-in` |
| Объяснение кандидата в подборке, вклад сигналов | `Disclosure`: clip-path + opacity, повторный клик разворачивает с текущего кадра |
| Приглашение отправлено | кнопка → статус через `Swap`, счётчик бюджета приглашений меняется без анимации числа |
| Входящие, непрочитанное | бейдж счётчика `pop-in` при появлении; новое сообщение переписки — `rise-in` 6px |
| Вердикт смены грейда, принятие или отказ | у каждого исхода своё движение и иконка, не только цвет |
| Диалоги | подложка fade, панель scale; шапка, прокручиваемое тело (`overscroll-behavior: contain`), видимый подвал; линия под шапкой при прокрутке; фокус на заголовок |
| `Select`, `Menu`, `Popover`, `Combobox` (технологии, теги) | fade + scale 0.95→1 + сдвиг 4px от якоря, `transform-origin` у якоря, переходы с `@starting-style`; закрытие быстрее; повторное открытие — с текущего кадра; подсветка пункта не анимируется |
| `Checkbox`, `Switch`, `Radio` | галочка по `stroke-dashoffset`, бегунок по transform, точка — opacity + scale |
| `Tooltip` | fade + scale 0.95 от якоря; следующий в пределах задержки — без анимации |
| Тосты | вход сбоку, выход быстрее; ошибка 10 с, остальные 5 с, hover — пауза; живут в скрытых `aria-live` регионах |
| Полосы прокрутки | ползунок проявляется при прокрутке и наведении, гаснет после паузы; затухание у краёв области |
| Пустое состояние, ошибка | `slide-in` |

### 5.3 Reduced motion [предл.]

«Мягче, а не ноль»: `--dur-*` → 1ms, `--stagger` → 0, сдвиги и scale нейтрализуются; элементы с
`data-motion="fade"` (Swap, вердикты, панели, плашки) получают короткий fade 160ms / 110ms; спиннер
заменяется текстом стадии; полосы уровня появляются сразу.

### 5.4 Примитивы `shared/motion/` [предл.]

Других способов анимировать нет. Образец — did_hack `frontend/src/ui/shared/motion/`:
`usePresence(open)`, `useLatched`, `<Swap swapKey>`, `useSlidingIndicator`, `withViewTransition`,
`useDetailsMotion`, `motionMs`, `readEasing`, `useReducedMotion`, `useLoadingIndicator`, `settleDelay`.

### 5.5 Тесты движения [предл.]

В CSS вне `tokens/` нет литеральных ms, `cubic-bezier`, `!important`; каждый `--motion-*` ведёт на
существующий keyframe; каждый `*-exit` короче входа; токена `--ease-in` нет; reduced motion сжимает
каждый `--dur-*`; у каждой строки таблицы 5.2 есть поведенческий тест на `data-state`; примитивы
покрыты юнит-тестами. Перед сдачей фичи с движением — проход скилом `review-animations`.

## 6. Единый стиль и свои элементы управления

**[утв.]** Визуальный стиль везде един: кабинеты, вход, PDF-профиль кандидата, письма, презентация,
отчёт валидации. Один источник токенов; HTML-материалы подключают копию CSS токенов, собранную
скриптом, а не переписанные значения. [предл.] **[утв.]** Дизайн-система — брендбук ФСП
(`брендбук (1)/`): синий `#402FFF`, красный `#EC1D35`, графит `#1B1C21`, линии-трассы. Шрифты: JetBrains Mono (единственный шрифт брендбука) — голос продукта: заголовки, навигация, кнопки, подписи, числа; Onest — только текст для чтения (план §1.4).
Как он переносится в токены и экраны — [frontend-plan.md](frontend-plan.md) §1.

**[утв.]** Все элементы управления свои: полосы прокрутки, выпадающие списки, меню, флажки, радио,
переключатели, числа, раскрывающиеся блоки. Один компонент на роль [предл.]:

| Роль | Компонент | Запрещено |
| --- | --- | --- |
| Действие | `Button` | `<button>` со своими стилями в фичах |
| Выбор из списка | `Select` | нативный `<select>` |
| Выбор с поиском, теги | `Combobox`, `TagInput` поверх `Popover` | самодельные абсолютные слои |

| Число, деньги | `NumberField`, `SalaryRange` | `<input type=number>` со стрелками |

| Раскрывающийся блок | `Disclosure` | голый `<details>` |
| Диалог, закрыть | `Dialog`, `CloseButton` | иконка `X` в других местах |

| Нет значения | `NoValue` (иконка-пустой узел + «не указано») | `—`, `-`, `n/a` руками |
| Иконка | `Icon` (lucide + свой набор `icon/brand/`) | SVG и эмодзи напрямую в фичах |

**[утв.] Иконки везде, визуальный стиль — бренд ФСП «узлы и трассы».** Линейные, обводка 1.5,
скруглённые концы и стыки, сетка 24, размеры 16/20/24/48. Свой набор для понятий продукта
(специализации, грейды, уровни доверия, «измерено», «погрешность», «соответствие») рисуется по тем
же правилам, фирменная деталь — залитый узел r=1.75 на конце или стыке линии. Иконка обязательна:
у пунктов навигации, кнопок действий, статус-бейджей, префиксов полей контактов и денег,
атрибутов в строках условий, пустых состояний (48px). Не ставится над каждым заголовком секции и в
прозе. Иконка-кнопка — с `aria-label` и тултипом; декоративная — `aria-hidden`. Цвет — как у текста
рядом. Одно понятие — одна иконка (`icon-alias`). Подробно — [frontend-plan.md](frontend-plan.md) §1.8.

Глобальные полосы — `::-webkit-scrollbar*` с ползунком-таблеткой (`background-clip: padding-box`) и
`@supports not selector(::-webkit-scrollbar)` → `scrollbar-width: thin` + `scrollbar-color`; цвет
ползунка анимируется через `@property --scrollbar-thumb-color` (did_hack `global.css`, `scroll-area`).

## 7. Стили

**[утв.]** Никаких огромных CSS. Стили локальные, без повторений, общее переиспользуется.

**[утв.] Две темы, светлая и тёмная.** Семантический слой задан дважды
(`:root[data-theme="light"]`, `:root[data-theme="dark"]`); палитра и компоненты общие, компонент
не знает, какая тема включена, и не пишет `[data-theme]` в своём модуле. По умолчанию — системная
настройка, выбор пользователя в `localStorage`, тема ставится до первой отрисовки (без вспышки).
Каждый семантический токен задан в обеих темах (тест), контраст ≥ 4.5:1 проверяется в обеих,
брендовые ассеты выбираются по теме через `BrandAsset`. PDF и письма — всегда светлые. Значения —
[frontend-plan.md](frontend-plan.md) §1.3.

- Глобальное — только `shared/styles/`: `global.css` подключает `reset.css` и
  `tokens/{palette,semantic,radius,space,typography,elevation,motion,keyframes}.css`; импорт один, в `main.tsx`. [предл.]
- Всё остальное — CSS Modules рядом с компонентом; модуль импортирует только свой компонент;
  селекторы начинаются с класса компонента; неиспользуемых классов нет. [предл.]
- Повтор: блок из 3+ одинаковых деклараций в двух местах запрещён — это компонент или токен. Общие
  куски — через `composes:` из `shared/styles/compose.module.css` (текст, карточная рамка, pill, stale),
  `layout.module.css` (раскладки шагов и действий) и `rows.module.css` (строки списков, колонка места).
  Файл ≤ 250 строк касается и их: новый общий кусок — в подходящий или новый модуль. `composes` — первой
  декларацией и только в селекторе из одного класса. [утв.]
- Литеральные цвета, длительности, кривые, тени, радиусы, толщины линий — только в `tokens/`; дальше
  только `var(--…)`. Компоненты берут семантический слой (`--surface-*`, `--text-*`, `--action-*`,
  `--border-*`, `--focus-ring`), палитру напрямую — нет. [предл.]
- Компонент объявляет свои локальные custom properties, модификаторы их переопределяют. [предл.]
- **[утв.] Сайт во всю ширину экрана.** Узкая колонка по центру с пустыми полями — паттерн
  ИИ-генерации и запрещена: у контейнера страницы и рабочей области нет `max-width`, поля у краёв
  24px (32px на ≥ 75rem). Ширину заполняют панели (сайдбар, список + деталь, фильтры + выдача +
  панель объяснения, форма + превью), сетки резиновые на `minmax()` и `fr`. Ограничение ширины —
  только внутри элемента, где его требует чтение: абзац прозы ≤ 70ch, одиночное поле ≤ 480px.
  На сверхшироком экране добавляется панель, а не растут поля. Проверка `no-page-max-width`:
  `max-width` в px/rem больше 480px или в `ch` больше 70 вне токенов запрещён. Раскладка по
  экранам — [frontend-plan.md](frontend-plan.md) §1.6 и §2.1.
- Брейкпоинты — только `30/48/64/75/90/120rem` (90 и 120 — для третьей и четвёртой панели), одна запись `min-width: Nrem` / `max-width: (N−0.01)rem`,
  так же в `matchMedia`. [предл.]
- Шкалы радиусов, теней, размеров текста, отступов фиксированы токенами, другие значения ловит
  проверка. Без градиентов и эмодзи в интерфейсе. [предл.]
- Шрифты — локально из `public/fonts` с `font-display: swap`, preload и лицензией рядом: на защите
  может не быть сети. Внешних ассетов нет (`remote-assets`). [предл.]

## 8. Доступность [предл.]

Контраст ≥ 4.5:1 (исключение — отключённые элементы); цель нажатия ≥ 44px у каждого самостоятельного
интерактивного класса; видимый `:focus-visible`; состояние не только цветом; клавиатура в
`Select`/`Menu`/`Combobox`: стрелки, Home/End, Esc, возврат фокуса; e2e с axe. Геометрию, фокус и
выравнивание тесты не видят — их проверяет живой прогон в браузере перед сдачей фичи.

## 9. Скилы

- **[утв.]** Весь фронтенд делается со скилами `impeccable` и `ui-ux-pro-max`; анимации — со скилами
  из раздела 5.
- **[предл.]** Скилы работают внутри этих правил: сырые палитры и шрифты из `ui-ux-pro-max` не берём,
  берём структуру, UX- и a11y-проверки. `frontend/DESIGN.md` и `frontend/PRODUCT.md` для `impeccable`
  пишутся руками как краткое описание токенов и продукта; значения живут только в `tokens/`.

## 10. Проверки `scripts/checks/` [предл.]

`npm run rules`, 29 проверок с ratchet-базами в `scripts/baselines`: file-length, no-comments,
package-size, package-subject, import-cycles, layers, cyrillic, jsx-text, css-literals, css-token-refs,
css-modules, css-duplicates, css-transitions, scale-tokens, token-layers, signal-scope, no-side-stripe,
touch-targets, contrast (обе темы и inverse), surface-ladder, motion-tokens, consistency, icon-alias,
global-styles, hover-gate, ts-timings, motion-libraries, remote-assets, accent-text.
Разделители «—» и «·» и ширина страницы пока проверяются глазами и тестом словарей.
Одним процессом на весь прогон, не процессом на файл: на Windows иначе медленно и нестабильно.

## 11. Порядок внедрения [предл.]

1. Biome, strict TS, `scripts/checks` с базами; генерируемая схема → `schema.gen.ts`.
2. Токены, `global.css`, reset, motion; `styles.css` удаляется по мере переноса.
3. i18n: словари, провайдер, переключатель; перенос `words.ts` и литералов JSX.
4. Раскладка FSD, примитивы `shared/ui`, перенос экранов на CSS Modules, снятие комментариев.
5. Примитивы движения и таблица 5.2, проход `review-animations`.
6. Тесты единства, общий CSS токенов для PDF-профиля, писем и презентации.
7. Разрезание файлов > 250 строк и снятие баз.

2. Дизайн-система — брендбук ФСП. Две темы, светлая и тёмная: обе родные для бренда (пары логотипов
