# Тест по вакансии: демо-вакансии

Как система строит тест по описанию вакансии — правило в [механиках, §6](mechanics.md#6-адаптивный-тест),
параметры `vacancy_test_items` и `vacancy_test_min_items_per_topic` — в [parameters.md](parameters.md).
Ниже — пять потребностей демо-работодателя `employer@demo.example` из `backend/seed_demo.py`, по одной
на специализацию. Таблицы собраны ответом `GET /api/employer/needs/{need_id}/test` на засеянном стенде;
пример задания при каждом запросе — новый экземпляр того же семейства.

В кабинете работодателя то же видно кнопкой «Тест по вакансии» в редакторе потребности и в подборке;
галочка «Приложить тест по вакансии» в диалоге приглашения отправляет тест кандидату. Кандидат проходит
его из приглашения, итог видит только пригласившая компания.

Что видно в таблицах:

- в тест идут ключевые и важные темы потребности; разный стек — разный состав тем: у бэкенда с
  Kafka и Redis есть «Очереди, кэши и распределённые системы», у бэкенда с Django и PostgreSQL —
  «Базы данных и SQL» (тест `tests/test_vacancy_test_domain.py`);
- задания делятся по весам важности методом наибольших остатков, каждой теме — не меньше одного;
- пример — семейство со сложностью ближе всех к требуемому уровню, то есть к порогу грейда
  потребности; два запроса дают разные экземпляры одной сложности (`tests/test_vacancy_tests.py`).
