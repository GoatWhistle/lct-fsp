# Развёртывание на публичном стенде

Подготовка к публичному запуску и сведения о предыдущей проверке локального проекта
`calibr-demo` (`scripts/demo.sh`). Публичное развёртывание не выполнялось: домен, TLS,
внешний SMTP и публичный OIDC требуют отдельной настройки. Ниже указан порядок подготовки;
он не является подтверждением готовности публичного стенда.

## Что нужно

Сервер с Docker и Compose v2, 2 ГБ памяти без локальной модели (стенд в покое — около 0,8 ГБ),
и внешний reverse proxy с HTTPS. Требование памяти — ориентир предыдущего локального
запуска, не результат нагрузочного испытания. Образы собираются из репо:
`backend/Dockerfile`, `frontend/Dockerfile`.
Compose публикует порты на `127.0.0.1`; сам по себе он не открывает сайт в интернете.

## Шаги

1. Клонировать репо, включить хуки не нужно.
2. Создать `.env` рядом с `docker-compose.yml` (образец — `.env.example`), файл не коммитится.
   Сгенерировать секрет командой `openssl rand -hex 32` и вставить результат в файл:

   ```bash
   SECRET_KEY=<сгенерированное значение>
   FRONTEND_URL=https://<адрес стенда>
   COOKIE_SECURE=true
   SESSION_COOKIE_NAME=calibr_session
   DEMO_MODE=false                         # true только на стенде показа
   ```

   `.env` не выполняет shell-команды: подстановка `$(openssl ...)` внутри файла не создаёт
   секрет. `COOKIE_SECURE=true` требует, чтобы браузер обращался к сайту по HTTPS.

3. До внешнего доступа настроить reverse proxy, TLS и OIDC согласно таблице ниже.
   Запустить `docker compose up -d --build`. Бэкенд сам применяет миграции и каталог, готовность —
   `GET /api/health` (healthcheck в compose), фронт стартует после него.
4. Демо-данные (только на стенде показа, нужен `DEMO_MODE=true`):
   `docker compose exec backend python seed_demo.py`. Без `DEMO_MODE=true` засев отказывается
   работать, а входа по паролю в его учётки (`@demo.example`) нет. Повторный запуск ничего не
   дублирует и не удаляет.
5. Проверка: `curl -s http://localhost:<порт>/api/demo/status` — `{"enabled": false}` в обычном
   режиме; `POST /api/auth/login` под демо-учёткой — 401; интерфейс открывается по `FRONTEND_URL`.

По предыдущему отчёту на `calibr-demo` проверены сборка образов, подъём, повторный засев,
закрытие демо-входа в обычном режиме, `SECRET_KEY` из окружения и атрибут `Secure` у cookie.
При редактуре документа эти проверки повторно не запускались. Точный контракт обычного
режима: вход по паролю демо-учётки — `401 invalid_credentials`, входы `/api/demo/employer`
и `/api/demo/candidate` — 404; `/api/demo/status` остаётся доступен и возвращает `enabled: false`.
Покрытие браузерных сценариев и пробелы записи описаны в [демо](demo-script.md#видео-и-покрытие-сценария).

## Изолированный локальный стенд

`scripts/demo.sh up` поднимает проект `calibr-demo` на портах 3100 (интерфейс), 8100 (API),
8180 (Keycloak), 8125 (Mailpit), 5532 (PostgreSQL) со своими томами, не трогая основной стенд;
`scripts/demo.sh seed` — повторный засев; `scripts/demo.sh down` — снос только этого проекта
вместе с его томами. Порты меняются переменными `DEMO_*_PORT`. Возврат из ФСП ID разрешён для
портов 3000, 8000, 3100 и 8100 (`backend/fsp_stub.py`, `keycloak/realm-fsp-id.json`).

## Чего нет

| Что | Статус |
|---|---|
| Домен и DNS | нет; `FRONTEND_URL` нужно задать под реальный адрес |
| TLS | нет, терминацию (Caddy, nginx, облачный балансировщик) ставит оператор; образ фронта слушает HTTP на 80, а `COOKIE_SECURE=true` без HTTPS вход ломает |
| Почтовый сервер | нет; в compose письма уходят в Mailpit и наружу не идут, для настоящего SMTP заданы `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM` в настройках бэкенда, но compose их не пробрасывает и такая связка не проверялась |
| Настоящий ФСП ID | нет; вместо него локальный Keycloak с тестовыми участниками (`admin` / `admin`, известные пароли) — на публичном стенде его нужно закрыть или заменить, redirect URI в realm прописаны под localhost |
| Keycloak для продакшена | стоит `start-dev`, это режим разработки |
| Резервное копирование PostgreSQL | нет, том `pgdata` без бэкапа |
| Локальная модель разбора текста (llama.cpp) | в этой проверке не поднималась; без неё работают правила |
| Мониторинг, лимиты запросов на периметре | нет |
