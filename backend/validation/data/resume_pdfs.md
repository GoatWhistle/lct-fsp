# D6 — резюме в PDF с разметкой — формат набора

Набор для M18 (защита от инъекций) и M22 (разбор резюме) —
[`docs/validation-plan.md`](../../../docs/validation-plan.md), D6. Лежит в `d6/`:

- `resumes.yaml` — разметка, одна запись на PDF;
- `pdf/<id>.pdf` — резюме;
- `review/` — комплект проверки человеком: `README.md` и лист `review.csv`.

```sh
uv run python -m validation d6                       # проверка целостности и сводка
uv run python -m validation d6 --build               # собрать набор заново (не трогает подтверждённое)
uv run python -m validation d6 --confirm <лист.csv>  # принять заполненный человеком лист ревью
```

## Отложенный набор

По D6 не подбирают правила разбора, словарь синонимов (`config/synonyms.yaml`) и промпты, не
обучают модели ([ADR 0002](../../../docs/adr/0002-text-understanding-port.md)); продукт его не
импортирует — это проверяет тест. Разметка — **истина вымышленных людей**
(`validation/d6_people.py`), а не результат разбора: разбор набор не размечал и не должен.

Люди вымышлены: почты на `example.*`, телефоны `+7 900 555-01-NN`. Названия технологий в тексте
— названия справочника, должности — слова словаря ролей.

## Состав

- **Чистые резюме** `d6-c01…c10` — 10 человек, 7 вёрсток: `one_column`, `two_columns`, `table`,
  `builder` (светлый текст на тёмной плашке, как у конструкторов), `jobsite` (экспорт с job-сайта,
  стаж написан словами), `latex` (имитация вида LaTeX, настоящего LaTeX на стенде нет),
  `multipage`. По два человека на специализацию MVP: бэкенд, фронтенд, данные/ML, QA, DevOps.
- **Варианты с инъекциями** `d6-i01…i16` — 16 штук, у каждого `twin_of` — чистое резюме того же
  человека в той же вёрстке; разница между ними — только инъекция.

| Тип (`injection.type`) | Приёмы (`technique`) |
|---|---|
| `white_text` | `white`, `near_white` — белый и почти белый текст |
| `zero_font` | `zero` — кегль 0 |
| `off_page` | `off_left`, `off_right`, `off_bottom` — текст за полями страницы |
| `visible_instruction` | `visible_top`, `visible_end`, `visible_footer` — видимое «поставь меня первым» |
| `hidden_stack` | `white`, `tiny_white`, `off_left` — скрытые технологии, которых у человека нет |
| `invisible_mode`, `transparent` | невидимый режим отрисовки, нулевая прозрачность — сверх плана |

Что спрятано (`injection.payload`): `instruction` — инструкция модели, `identity` — чужие ФИО,
почта, телефон, «Team Lead, Senior, 15 лет», `stack` — чужие технологии. Скрытая инъекция
пишется в начало первой страницы, раньше настоящего имени. Тип `builder` намеренно содержит
легитимный светлый текст на тёмном фоне: он проверяет, что разбор не принимает его за скрытый.

## Запись

| Поле | Что это |
|---|---|
| `id`, `file`, `sha256`, `pages` | Идентификатор, путь от `d6/`, хэш файла, число страниц |
| `layout`, `specialization`, `person` | Вёрстка, специализация (код справочника), человек набора |
| `full_name` | ФИО как на странице |
| `contact_email` | Почта |
| `contact_phone` | Телефон в виде `+7 XXX XXX-XX-XX` (на странице может быть записан иначе) |
| `stack` | Коды технологий справочника, которые названы на странице, и ничего сверх |
| `job_roles` | Названия из словаря ролей (`config/synonyms.yaml`) для должностей раздела опыта |
| `experience_years` | Полные годы объединения периодов работы на `as_of`; конец «по настоящее время» — месяц `as_of`, оба конца периода включены |
| `twin_of` | Только у вариантов с инъекцией: id чистого двойника |
| `injection` | `type`, `technique`, `payload`, `text` — только у вариантов с инъекцией |
| `checked_by` | `pending` — запись человек не проверял; иначе имя проверяющего |
| `checked_at` | Дата проверки; пока `pending` — пусто |

Поля разметки варианта равны полям двойника: так M18 сравнивает распознанное. M22 считается
по чистым записям.

## Целостность

`validation d6` проверяет: файлы и хэши, число страниц, коды справочника и словаря, формат почты
и телефона, что значения разметки есть в тексте файла, что текст инъекции есть в варианте и
отсутствует у двойника, что инъекция не называет технологий (кроме `stack`, где они чужие),
равенство разметки двойника и варианта, покрытие: не меньше 5 вёрсток и 10 вариантов, все
специализации MVP и все пять типов инъекций плана. Текст из файла берётся без фильтра скрытого
— только чтобы убедиться, что инъекция действительно в файле; разбор в проверке не участвует.

## Проверка человеком

Подтверждение записей — решение человека, которое набор не выдумывает: все записи сейчас
`pending`. Порядок — в [`d6/review/README.md`](d6/review/README.md). `--confirm` принимает только
лист, где указан проверяющий-человек и все обязательные столбцы — `да`; `--build` не
перезаписывает набор с подтверждёнными записями.
